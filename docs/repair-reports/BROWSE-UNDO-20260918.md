# 浏览恢复、最近操作与首页设计

## 交付范围

- 同标签页的页面筛选与位置恢复，刷新、侧栏切换、浏览器前进后退均复用。恢复前核对照片数量、快照边界及锚点；不匹配时保留筛选，从列表重新浏览。
- `recent_operations.py` 独立注册 `/api/organize/` 接口，使用现有 operations 表与同一数据库事务。新增补录、附近地点修改的操作回执和撤销；人物合并复用原安全撤销接口。
- 页面「整理 → 最近操作」，照片和人物详情也有入口。后续修改冲突时整批拒绝；网络丢失撤销响应时查回执，不重复修改。
- 旧后台继续支持原补录接口，页面明确表示该次没有撤销支持。未自行重启正式后台，未改正式照片或人物数据，未重新识别人脸。
- 三个首页推荐方向全部纳入设计；仅生成设计稿，未实施首页。见 `docs/design/home-20260918/README.md`。

## 限制与诊断

- 正式后台未由本任务更新，源码验证不等于正式服务已加载撤销接口；绿色包未重建。新增 Python 模块已加入打包清单。
- 地图框选在并行任务中新增了未来照片自动命名规则。本轮不把「只恢复当前照片」误称为完整撤销，因此该类规则不纳入最近操作。普通补录、照片附近地点修改和人物合并仍按上述范围交付。
- 曾执行整个 M1 旧套件：18 项通过，1 项既有文案断言失败。`test_state2_is_visible_and_get_does_not_run_face_model` 期望“待恢复”，当前实现为“人脸信息已保存，预览仍待完成”。本轮没有改该功能或放宽该断言，不能把旧套件整体记为通过。
- 早期将多个使用不同环境变量的旧套件放入同一 Python 进程，出现缓存配置指向已清理测试目录的问题；改为独立进程后，该目录错误消失。
- 并行任务两次覆盖主程序中的撤销接入。最终使用独立模块和最小注册点，在其结束后重新接入并完成最终回归；保留其地图规则改动。
- 自动审批拒绝删除本轮早期失败测试临时目录，返回“策略阻止”，未提供进一步原因。临时目录保留，未通过替代删除路径绕过。
