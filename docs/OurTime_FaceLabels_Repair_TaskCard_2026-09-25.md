## 1. 完成后，用户应当看到什么

1. 同一张脸在人物统计、照片标签、样式预览及点击操作中使用相同的状态判断。只有别名的已命名人物，不再一处显示姓名、一处被当作“＋”。
2. 调整主题、字号、字体、透明度后，当前标签和设置预览一致；需要改变尺寸时重新测量、重新排布。刷新后保留设置。
3. “恢复外观默认”立即生效，刷新后仍有效；不清除任何照片的手动位置，不修改真实姓名、别名或人物归属。
4. 自动模式下，一张照片内中文竖排、英文横排各自完整成立。横排的不只是字，底板、留白、字距和装饰方向也匹配。
5. 默认主题字体来源稳定；素笺、茶棕、暗朱继续使用既有内置字体合同，不因重构全部退成普通黑体。
6. 照片显示变小时，人名题签仍按原比例一起变小；不偷偷增加固定大字号、不突然把所有标签扩大。完整姓名可通过清晰的按需提示读取。
7. 素笺、茶棕的底板随文字伸长，只拉伸直边中段，角花不被拉扁、拉长，不出现“双重边框”。
8. 相同条件下，设置预览、照片上的标签和导出图具有一致的内容、字体、配色、方向、底板和位置关系。
9. 已保存的手动位置还在；切换智能排布后可以回到自定义位置。只有明确的“清除本张自定义排版”动作可以删除这些坐标。
10. 最终能够指出“改了什么、删了什么、为什么安全、哪些样图证明效果、哪些还未验证”，而不只交付一段完成说明。

**不接受的替代交付：** 只改 CSS；只通过静态检查；只提供设计建议；只展示一张放大的标签特写；换上更花哨的底板；因为截图看起来正确就忽略位置保存和导出。

## 2. 权限、改动范围与安全边界

### 2.1 开始前必须读取

读取当前仓库的 `AGENTS.md`、`README.md`、有关标签/导出/测试的现行说明，以及本任务卡。历史文档只作背景，不能覆盖当前明确行为。

本任务卡提出的新修复目标优先于旧代码中已确认的问题，但**不能用“修复目标”作为突破数据安全、改变原有业务合同的理由**。发现冲突先记录，并采用最小、不破坏用户数据的实现。涉及正式写入、部署或不可逆操作时停在该边界。

### 2.2 正式运行目录和开发目录必须隔离

当前仓库说明明确：正式服务会直接从磁盘读取前端静态文件。因此，**不重启服务也可能因修改 `web/` 而影响正式界面**。

执行步骤：

1. 只读检查当前目录、分支、HEAD、remote、工作树状态、现有 worktree 和正式服务的代码/数据目录。
2. 不在正式服务正在读取的代码目录内边改边试。优先新建独立 `git worktree`，使用独立任务分支。
3. 若原工作树存在未提交改动，先记录文件及归属。禁止 `reset --hard`、`clean -fd`、覆盖文件或擅自 stash；不把用户未提交修改提交进本任务。
4. 以实际当前版本为实施起点。参考 SHA 用于对照，不要求回退到它。若相关未提交改动不可忽略，采用隔离副本/补丁副本复核，保留原文件；无法安全区分时报告具体阻塞，不盲目覆盖。
5. 测试用独立浏览器 profile/context，不能拿用户日常使用的浏览器存储做清空和迁移实验。
6. 后端测试只使用明确指定的临时数据目录和空闲端口；不能仅因为端口改成 8766/其他端口就认为已经隔离。
7. 启动前校验代码根目录、解析后的 `PHOTO_LIBRARY_DATA`、静态文件根目录及导出输出目录；启动后核对实际服务身份。任何一项指向正式库，即终止该测试进程。
8. 不复制整个 `config.local.json` 到测试目录。只按需传递已核实的配置，防止其中的路径把测试重新指向正式数据。
9. 结束时只关闭本次创建并记录 PID 的测试进程。不得按进程名批量杀 Python、Chrome、uvicorn。

**注意：** `PHOTO_WEB_ROOT` 等配置是否在当前执行入口真正受支持，必须读代码确认；设置了一个环境变量不代表隔离已经生效。

### 2.3 允许修改的区域

| 区域 | 允许内容 | 限制 |
|---|---|---|
| `web/viewer.js` | 标签状态、主题设置、预览、方向、测量、渲染调度、必要交互接线 | 不重写整个 viewer，不改变照片序列和导航合同 |
| `web/viewer-overrides.css` | 标签和标签设置面板相关规则 | 不顺便重做 signature、收藏、地点地图及整个工具栏 |
| 新的 `web/face-label*.js/.css` | 按职责抽取的标签模块与共享样式 | 保持静态 HTML/CSS/JS，无新框架、无构建链 |
| `web/index.html` | 新模块的明确加载顺序、必要引用 | 不改首页结构，不重复加载脚本/样式 |
| `web/app.js`、`web/style.css`、`web/appearance.css` | 必要的公共接口接线、已证明被替代的标签专属规则 | 每一处改动需说明原因，不全局替换字体/颜色/按钮样式 |
| 标签资源配置和现有导出代码 | 必要的资源可用性、CSS/字体收集适配 | 仅确有依赖才改；不扩大文件访问白名单，不改导出业务合同 |
| `validation/` | 聚焦用例、隔离运行入口、脱敏报告 | 旧测试按等价语义适配，不能删断言或把失败改 SKIP |
| 当前项目说明 | 标签合同及运行说明的必要更新 | 不记录个人照片路径、真实姓名、私人数据 |

后台 `app.py`、`ourtime_config.py`、`photo_export.py` 不是默认重构范围。若修复必须触及，限定为标签素材解析/导出样式接线等小改，增加聚焦测试，并列入最终报告；不得碰数据库 schema、人物识别与合并策略。

### 2.4 禁止事项

- 不扫描或重扫正式照片；不重跑人脸识别、embedding、GPU 补扫、聚类、自动路人整理。
- 不修改识别阈值、匹配 margin、姓名去重/同名合并规则、人物关系和照片排除语义。
- 不对正式 `data/`、数据库、缩略图、人脸裁剪、原图、EXIF 执行测试写入或清理。
- 不调用正式环境的命名、合并、拆分、路人、位置保存、位置清除等写接口。
- 不自动启动、停止、重启、升级、部署正式 8765 服务；不修改它的启动器、配置或端口。
- 不把用户照片、真实人名/别名、GPS、绝对路径、数据库、日志中的私人数据、浏览器存储快照、字体文件打包给外部系统或推送到 GitHub。
- 不使用外部 CDN、远程字体、第三方图片接口完成标签显示；不新增遥测。
- 不增加第五款主题；不删除现有四款；不换名后伪装成保留；不恢复按字数切换多张底板的旧方案。
- 不通过隐藏姓名、删除人脸、缩小到无法解释的尺寸、提高遮挡阈值来让布局测试通过。
- 不用新增 `!important` 和不断提高选择器权重作为主要收口方法；已有必要的 `[hidden]` 等例外单独说明。

### 2.5 真实照片的安全使用方式

优先使用已有隔离测试样本。视觉精修还需少量本地真实样图，建议 6—8 张即可，不全库遍历。

只读读取所选照片及其已存在的人脸框/人工位置，按需复制少量图片到隔离区；测试内的人物名使用“陈宁”“李安”“Alex”等虚构名字。不要重新做人脸识别，不把完整正式库复制进测试。

需要读取 SQLite 时使用只读连接并限定查询范围；不运行正式库的应用 lifespan、迁移、checkpoint、VACUUM 或修复脚本。不得简单复制一个正在使用 WAL 的 `.sqlite3` 文件后宣称已获得一致备份。

私人样图、原始截图、trace、HAR 和映射表只保留在本地明确排除提交的目录。公开报告用样例编号和相对路径；仅改名/遮住路径并不等于一张真实人像截图已适合公开。

基线与修复版使用同一 manifest。照片不是只要“看起来类似”即可替换；必须相同图片、相同窗口、相同设置。每张脸要有有效且唯一的测试 `faceId`，不让缺少 ID 的 fixture 掩盖缓存/保存串写问题。

**P0 出口：** 完成安全核验、调用关系、问题复现和测试盘点；留下基线截图/失败断言。无需等用户确认，可进入 P1。

## 5. P1：先修逻辑，不改变四款主题的视觉定位

### P1-01｜统一人物标签状态和文字解析

**目标：** 对同一份 face 数据只做一次权威解释，其他地方消费结果。

建议建立纯函数 `resolveFaceLabelState(face, aliasMode)`，名称可适配项目。返回值至少包含：`kind`、`isNamed`、`displayText`、`accessibleText`、`faceId`、`personId`。不要在这个函数内改数据库、改 face 原对象、写 localStorage 或操作 DOM。

**判定顺序与边界：**

1. 使用接口既有的数据类型规范化 `ignored`；不能让字符串 `"0"` 因 `Boolean("0")` 被误判为路人。正常 API 值与容错值分开测试。
2. `ignored` 为真时，归类 `passerby`，保留当前路人标记语义；不能因为还有旧姓名就自动恢复成已命名。
3. 姓名和别名先 trim。姓名中的既有占位值 `待核对`、`命名`、`路人` 不作为有效姓名；不擅自扩大名单，不用模糊匹配误伤含这些字的真实姓名。
4. 有有效姓名或非空别名，按当前 `faceHasUsableName` 的既有展示语义归类为 `named`。只修展示一致性，不改后台确认/匹配规则。
5. 两者都没有，归类 `pending`。不能显示 `undefined`、`null`，也不能把占位文字作为普通姓名绘制。
6. 别名模式：`off` 优先有效姓名、无姓名回退别名；`with` 有不同的姓名和别名则显示 `姓名 / 别名`，相同内容不重复；`only` 优先别名、无别名回退姓名。
7. 显式传入的有效 `aliasMode` 必须生效，不能函数接收了参数却仍读取另外一个全局模式。旧布尔参数若仍有调用，统一适配后再收口。
8. 本轮保留既有 `姓名 / 别名` 内容合同，不另做双列副签、折叠姓名或缩略姓名。别名的艺术化重排属于后续设计，不混入本次修复。

**接入范围：** 人物概况/HUD、标签 class 与标记、预览示例选取、点击进入命名或管理的判断、布局时是否参与已命名竖排中位数计算、当前照片的相关人物展示。不要顺手改变首页推荐或后台人物列表的业务筛选规则。

**人数与脸数：** 保留人物统计按有效 `personId` 去重的既有粒度，照片标签按 `faceId` 绘制；不能为了两者数字一样而删脸。异常缺失 ID 不得统统合成同一个 `NaN` 人物，按既有合同报错或安全处理并记录。这个去重不是人物合并。

**验证：** 同一 fixture 同时断言解析结果、HUD 分组、DOM 类名、预览文本和点击路径，而不只测试新纯函数。

### P1-02｜所有外观变更走同一条更新链路

建议使用一个统一入口，负责：校验输入→更新内存偏好→应用主题能力→保存当前偏好→同步控件和预览→按需安排测量/重排。

**修复步骤：**

1. 统一 `applyFacePreset`、`updateFaceStyle`、字体选择、透明度滑块及恢复默认的调用链。
2. 将按钮文案改为“恢复外观默认”；只恢复当前标签外观及原按钮既有的未命名标记默认，不重置别名模式、文字方向、显示开关、幻灯片间隔或照片手动坐标。
3. 点击后保存并重新同步预览。字号/字体/留白变化需要重排；纯颜色变化可只重绘，不能每次产生无意义的多轮布局。
4. 不通过清空整个 localStorage 或删除偏好 key 来实现恢复默认。
5. 保存失败时内存显示可继续工作，但必须有一次明确、克制的提示，不能谎称刷新后仍会保存。不要每次滑块 input 都弹报错。
6. 保留隐藏姓名的状态：用户关闭姓名显示后改样式，不得因重排又把姓名层强行打开。

**验证步骤：**

- 先设置非默认主题/字号/字体/透明度，再点击恢复；检查当前标签、预览、控件、localStorage。
- 刷新后重新进入同图，四处结果一致。
- 图 A 先保存自定义位置，再恢复外观默认；核对坐标保留、位置清除 API 的调用次数为 0。
- 切换图 B，确认没有把图 A 的临时状态写到 B。
- 对 localStorage 抛出异常，确认不阻塞看图，并准确提示。

### P1-03｜建立一个权威方向结果

**必须保持的产品规则：**

| 文本类型 | 自动 auto | 横排 horizontal | 竖排 vertical |
|---|---|---|---|
| 中文姓名 | 竖排 | 横排 | 竖排 |
| 中英混合姓名 | 竖排 | 横排 | 竖排 |
| 纯英文/拉丁字母姓名 | 横排 | 横排 | 仍横排，保留既有英文例外 |
| 待命名/路人标记 | 保持标记形态 | 保持标记形态 | 保持标记形态 |

不能为了让“强制竖排”字面上更一致而悄悄改变英文例外。说明文字可写“中文竖排，英文保持横排”，让用户知道实际行为。

**实施：**

1. 先获得实际显示文本，再解析最终方向；显示“姓名 / 别名”时按整个显示文本判定。
2. 将最终方向写在每个标签的单一 class/data 属性上，照片标签与预览同用；整层状态仅用于面板/工具状态，不再决定单个英文标签的金边与留白。
3. 同步处理 writing-mode、text-orientation、字距、padding、底板图、切片方向、暗朱装饰边位置。
4. 顶部按钮和详细菜单读写相同 `faceDirMode`；改任一入口后另一入口、预览和实图立即同步。
5. 对 `A`、`A. B.`、`Anne-Marie`、带重音拉丁字母名字增加边界测试。不能只因字母数不足 2 就把明确英文名竖排；不将任意“不是中文”的文本都当英文。
6. 对扩展汉字、中英混合、数字与标点的处理明确记录；其他文字系统没有既有明确规则的，保留现有回退，不扩展成多语言排版工程。

**重点回归：** 暗朱主题自动模式下的英文，与同文本强制横排时，在相同倍率下字距、padding、装饰边和底板应一致；旁边的中文仍为竖排。

### P1-04｜偏好迁移只在入口做一次，不能改变用户选择

**目标：** 运行时一个字段只表达一件事；旧字段仍能被安全读取。

1. 优先保持现有存储 key `ourtime.viewer.preferences.v2`。确需增设内部 schema 版本时，提供幂等迁移和回滚兼容说明，不直接删除旧 key。
2. `faceAliasMode` 的 `off/with/only` 任一有效值都优先于旧 `faceAlias`。尤其检查“新值 off + 旧布尔 true”不能读回 with。
3. `faceDirMode` 和 `faceDirectionVersion` 按现有版本迁移意图处理：老安装首次进入中文优先自动模式的规则保留；已经明确选择过的模式不能每次加载被重置。
4. 当前运行不再维护两个可以分别变化的 `faceAlias`/`faceAliasMode`、`faceVertical`/`faceDirMode`。仍有旧调用或导出依赖时保留只读派生适配，不保留双向独立状态。
5. 参考旧主题映射 `outline→tea`、`ink/paper/cinnabar→classic`，以及特定旧 classic 配方的精确迁移。当前本地已有更完整规则则保留；不能把所有 classic 用户自定义都认作旧默认覆盖掉。
6. 审查旧 `faceLabelPosition`：当前照片排布模式及已保存坐标才是权威，不让一个残留全局偏好覆盖已有手动位置。全仓核对调用后再停止写入旧字段。
7. JSON 解析结果必须是适用的对象；损坏 JSON、null、数组、错误类型、未知 theme、安全范围外数值都走可解释回退，不让 NaN/Infinity 进入 CSS。
8. 数值范围沿用当前主题控件合同；不要擅自扩大/缩小滑块可选范围。颜色和自定义字体字符串按当前合法格式处理。
9. 不触碰无关偏好。纯“加载/迁移”过程不发任何人物或坐标写请求。

**验证：** 冷启动、二次加载、刷新、恢复默认、旧主题、有效新值与旧字段冲突、非法 JSON。迁移重复执行结果必须不再变化。

### P1-05｜字体和底板资源完整性

- 核对 `@font-face` 声明和 `faceFontStack` 的真实名称，默认 `kai` 优先使用现有内置 `LXGW WenKai GB Screen`，保留必要系统回退。

- 不安装系统字体，不更换或打包现有字体二进制，不为本轮引入新字体下载依赖。

**底板处理：**

| 主题 | 竖排资源 | 横排资源 |
|---|---|---|
| 素笺 ivory | `/api/face-label-bg/1.png` | `/api/face-label-bg/7.png` |
| 茶棕 tea | `/api/face-label-bg/4.png` | `/api/face-label-bg/8.png` |

7. 失败缓存必须有可恢复路径；不能把第一次 false Promise 永久缓存到整个会话都不可恢复。成功资源可缓存，重试次数有界。
8. 不新增更宽的后台静态目录访问能力；素材仍限既有白名单，不能接受任意用户路径或 URL。

**验证：** 四个资源逐个缺失；竖版有/横版无；200 损坏文件；全部缺失；加载慢；恢复后重新选择。每个场景同时看预览、中文标签、英文标签及用户偏好。

1. 标签使用的 stylesheet 就绪后再做最终测量。若保留动态注入 CSS，处理其 load/error；若改为静态加载，明确加载次序并删除重复注入逻辑。
2. 等待本次标签实际使用的字体/图片，而不是无条件阻塞所有字体。字体失败要使用回退测量，不能让姓名无限等待。
3. 对字号、主题、方向、别名变更以及图片尺寸变化使用统一调度；相邻 input/resize 在一帧内可合并，不能每个标签独立触发整组重排。
4. 测量/字体回调携带当前照片 ID 和渲染 generation/revision。等待时用户切到了 B，A 的回调不能重绘 B 或把 A 的样式状态写回。
5. 保持“新照片和它的人名一起呈现”的既有合同；不得新图配旧姓名、旧图配新姓名。
6. 正在拖动时不以背景重排抢夺指针；拖动结束、取消、关闭、pointercancel 都正确解除状态。
7. 标签由纯色/透明度变化导致的重绘，不应清除当前焦点或多次绑定事件。
8. 如使用 ResizeObserver/字体事件，防止自身尺寸变更触发无限循环；关闭查看器时释放或停止不需要的监听和计划任务。

## 6. P2：统一组件与职责，再有证据地删除旧代码

### P2-01｜形成一个可维护的小型标签系统

推荐职责如下；文件名仅为建议，可按当前仓库习惯合并，但不能仍有多套独立状态或主题定义。

| 职责 | 输入/输出 | 不应承担的工作 |
|---|---|---|
| 标签 model / preferences | face + 模式→展示状态；旧存储→规范化偏好 | 不访问正式库，不操作 DOM，不发人物修改请求 |
| themes / resources | 主题 key→默认值、字体选项、控件能力、方向资源与切片参数 | 不决定人物是否已命名，不决定数据库位置 |
| visual / renderer | 展示状态 + 有效主题 + 方向 + scale→统一标签外观 | 不修改姓名或合并人物，不另存一套偏好 |
| layout | 人脸框、真实标签尺寸、照片边界、手动位置→位置与诊断 | 不加载字体，不猜名字，不写数据库 |
| controller（可留在 viewer） | 绑定事件、安排重排、调用现有保存队列、同步预览 | 不重新实现上述规则 |

可落成 2—3 个 JS 文件加 1 个 CSS 文件，不为追求“架构”拆成十几个微模块。保留 `app.js` 的公共工具先定义、先加载的约定；不用框架替换当前静态前端。

**接口约束：**

- 使用明确的参数、返回结果和 JSDoc 描述数据形状。核心纯函数可在无浏览器环境测试。
- 允许一个明确的命名空间或当前项目一致的导出方式，不新增大量散落全局变量，不创建全局事件总线。
- 现有其他脚本或测试需要的入口可保留薄适配层；适配层只能转发/转换参数，不能复制业务逻辑。
- 本轮不重写位置提交队列、operation ID、viewer 的图片切换 generation 系统。
- 旧入口删除前检查运行时代码、HTML 内联调用、测试的字符串提取、导出捕获与文档中的有效入口。

### P2-02｜主题描述和能力只有一个权威来源

统一主题描述至少包含：key、显示名称、默认字号与字体、允许字体集合、允许调整的字段、文字色/底色/透明度/圆角/留白/阴影的默认值、不同方向的底板 URL 与切片信息。

**不是要求把全部 CSS 写进 JavaScript。** 合理分工是：JS 管数据和能力，CSS 管共享视觉规则；主题数值与资源不再同时在 preset、preview 和 live 三处各保存一份。

- 字体下拉、滑块、禁用状态、预览和实图均依据同一主题能力。
- 素笺字体固定；茶棕和暗朱维持各自三种字体，不开放本机任意字体替换其主题合同。
- 素笺/茶棕的字号与底板透明度保留可调，其余当前固定项不要解锁。
- 默认主题保留当前允许的自定义能力。
- 暗朱的文字色、底色、透明度、圆角等按当前有效合同保留。若“文字阴影”等控件实际被 CSS 固定为无效，需据实禁用并说明，而不是保留一个可以操作但不生效的控件。
- 切换主题时清理上个主题残留的专属变量，避免 PNG URL、边框、字体残留影响另一主题；同时不能清空用户其他设置。

### P2-03｜实图和预览使用相同视觉组件

实现共享的标签视觉类/构造函数，实图可以是可交互 button，预览可以是非交互 span。**两者复用同一外观规则，区别只是容器、交互和显式倍率。**

实施顺序：

1. 先列出现有实图/预览的差异：font-family、font-size、weight、line-height、letter-spacing、padding、border、radius、text-shadow、底板伪元素与方向资源。
2. 抽出共同视觉类，保留必要现有 `.face-name` 和定位/导出相关属性；不为好看而一次更换全部 DOM 结构。
3. 把绝对定位、鼠标命中、拖动高亮、手动标记等放在外层职责；预览不携带可提交的 faceId/personId，不响应命名和拖动保存。
4. 统一方向后的共享样式按单标签方向生效；不得依赖“预览在某个父容器里所以另打一遍样式”。
5. 删除真正被共享规则替代的预览专属外观，只保留预览容器排版。
6. 不使用 Shadow DOM/独立 iframe 隔离实际标签；这会额外增加当前导出快照采集的成本，不属于本轮。
7. 每抽取一部分就运行组件比较和一次导出用例，不能等整个重构结束后才发现导出拿不到新 CSS。
8. 姓名、别名和字体名称属于输入数据，保留现有转义/校验；文本优先使用 `textContent`，不可因组件改造而把姓名当作 HTML 或 CSS 片段注入。引号、尖括号与 `&` 必须正常显示，不产生额外元素或脚本。

**一致性测试：** 在相同文本、同一主题、方向和 `scale=1` 下，预览与实际标签的相关 computed style 相同，宽高差在同浏览器同 DPR 下不超过 1 CSS px。差值只允许明确的亚像素舍入，不允许用 1px 容差掩盖不同 padding 配方。不同外层位置与 hover 状态不参与这项静态比较。

### P2-04｜原缩放公式和位置合同必须保留

设 `H` 为照片在浏览器内的实际显示高度，`r` 为人脸框高度占原图高度的比例，则参考现行逻辑：

```text
normalizedFaceHeight = r × 900
faceFactor = clamp(0.4 × normalizedFaceHeight / 56, 1, 1.6)
photoFactor = max(0.12, H / 900)
labelScale = faceFactor × photoFactor
```

- 中文及中英混合的已命名竖排标签：同一照片使用这些标签对应人脸高度的中位数计算统一 faceFactor。
- 横排姓名：按本人脸高计算 faceFactor。
- 字号、底板、主要留白使用同一 `--face-scale`。不把照片显示高度影响乘两次。
- 未命名/路人标记继续保持现有 24px 命中区域及主题独立形态，不随照片 scale 改变。
- 照片高度为 900→450→300px、faceFactor=1 时，15px 基础字号应依次为 15→7.5→5px。这是合同回归，不可把最后两者“修复”为固定 12px。
- `0.12` 是照片比例因子的下限，不是把最终字号强制固定，也不是把脸高系数的下限改成 0.12。
- 读取有效人脸框；缺框/非法尺寸不能编造人脸位置，也不能令布局出现 NaN。安全跳过无法定位的框，并在测试/诊断中记录原因。

**位置和碰撞：**

- 保存值依然是相对照片的中心点比例；照片平移/缩放/窗口变化不能产生累计漂移。
- 全仓统一获取手动位置和当前照片排布模式，不引入另一套隐藏坐标缓存。
- 切换智能/左右/上下布局不删除数据库坐标；已有坐标默认仍进入自定义模式，回到自定义可恢复。
- 中文智能排布保留“偏左、略下；右侧外缘有空间可向右”的原则，不在本轮替换搜索算法或调松约束。
- 标签重叠比 = 两标签交集面积 / 两者较小面积，上限 0.05。
- 单标签对某张脸的覆盖比 = 交集面积 / 该脸框面积，上限 0.35。
- 估算眼部区继续单独避让，不把它描述为真实眼睛关键点。
- 对可解固定样本，以上限制必须满足；对明显无法容纳的样本，保留姓名与用户位置并显示明确诊断，不假报 `layoutValid=true`。
- 几何验收使用浏览器实际测得的标签外框、人脸框和图片边界；不能只相信算法自己写入的 `data-layout-valid`。
- 如果实际视觉外框与命中区域分离，记录二者；不能拿人为变大的隐藏点击区域作分母，把视觉重叠率稀释掉。

### P2-05｜清理台账：删什么、留什么，都有证据

至少对以下候选检查：旧 `faceAlias`/`faceVertical`/`faceLabelPosition`、`faceLabelSide`、未使用的 direction 参数/局部变量、`long-name` 配套逻辑、旧主题注释、重复横排选择器、预览重复样式、动态注入的旧覆盖层。

**删除步骤：**

1. 全仓搜索符号/选择器/资源名；不仅搜索 `web/`。
2. 检查动态字符串、事件处理、导出白名单及测试提取源码的依赖。
3. 对状态字段判断它是“旧数据读入兼容”“现役运行状态”“只写不读”还是“外部接口”。
4. 无运行用途且无兼容职责的才删；仍需迁移的集中保留，不能继续散落。
5. 清理所有已替代的旧规则，不在文件末尾再放一大块覆盖来掩盖旧实现。
6. 删后跑实际行为和导出测试，并在台账记录替代位置。

台账格式：`旧符号/文件位置｜保留/删除/适配｜引用证据｜替代入口｜关联测试`。

不要把“代码减少了多少行”当验收标准。新增测试/类型说明可能使总行数增加；关键是权威来源更少、依赖更清楚、没有双轨实现。

**P2 出口：** 共享组件已生效；全部方向的预览/实图一致；安全迁移仍在；导出未破坏；删除清单可复核。

## 7. P3：视觉精修——保持风格，修正不一致和粗糙细节

### 7.1 四款主题的视觉合同

以下是本轮设计目标；颜色值为参考版本的起点，不是声称这些值已经通过真实照片验收。

| 主题 | 保留的性格与字体 | 当前主要起点 | 本轮精修重点 |
|---|---|---|---|
| 默认 classic | 日常浏览、轻量、暖白字；默认楷体来源固定 | 13px；字 `#f6f1e6`；深底 `#141812`；透明度约 0.50；圆角 10 | 清楚、安静、留白均衡；避免厚重光晕 |
| 素笺 ivory | 暖浅纸色、深赭文字、屏幕文楷 | 15px；字 `#5a2f28`；底板透明度约 0.76 | 文雅但可读；薄边框；文字与角花保持距离 |
| 茶棕 tea | 暖棕底板、暖米白文字、三款毛笔字 | 16px；字 `#f7ead8`；底板透明度约 0.66 | 笔意不糊成团；装饰不与字形争夺注意力 |
| 暗朱 accent | 深朱色题签、暖金细边、三款题签字 | 15px；字 `#f4e4cb`；底 `#6f302c`；透明度约 0.84 | 横竖装饰完整转换；金边、阴影和字距不过强 |

**允许微调：** 共享留白、字距、边线/阴影强度、面板层级及必要对比度。在默认值上有变更必须记录旧值、新值、样图证据；不批量覆盖已经存在的用户自定义值。

**不允许：** 凭个人偏好换掉整款底板、重画角花、把四款全部变成同一风格、把全站字体一起替换、添加与标签无关的大面积装饰。

### P3-01｜字体与字距

1. 检查最终实际使用的字体，不只看 font-family 字符串。核对字体资源加载、代表性汉字/英文是否缺字、是否出现异常系统回退。
2. 素笺必须使用现有内置文楷；茶棕/暗朱分别检查三款字体，不以默认字体一张截图代表所有选项。
3. 书法字体不得使用浏览器合成粗体来“增强存在感”。需要更清楚时先审视字号、背景、留白，不自动把字重加粗。
4. 中文竖排的字符应直立；英文横排按正常字符顺序，不出现每个字母直立排成一列。
5. 暗朱的英文横排不沿用中文竖排过大的字距和左右竖向金边；横排用其横排装饰合同。
6. 在 `scale=1`、0.5 与实际合影显示尺寸检查字形。放大截图只用于观察细节，不能证明缩小时能读。
7. 别名内容本轮仍保持同一阅读顺序；不为了缩短题签丢掉姓名或别名。

### P3-02｜文字、底板与留白

1. 底板用当前四张资源，通过现有九宫格/边框切片思路伸缩；不把整张 PNG 直接拉长。
2. 先在 `scale=1` 测 1/2/3/5/8 个汉字，再测长英文和混合名；题签长边随文字增长，短边不随字数无意义变粗。
3. 横排应使用 7/8 图及正确方向参数，不简单把整个 button 旋转 90°，导致文字/点击/坐标都旋转。
4. 不能同时叠加 PNG 自带外框与第二层 CSS 实线框；预览与实图都检查四角。
5. 上下/左右留白需让视觉重心稳定；书法字形不一定几何中心即视觉中心，允许主题级的小幅修正，但不能按具体人名逐个写补丁。
6. 普通姓名字形不碰框、不穿角花；行盒外的书法笔画也要在真实截图中观察。只比较 `offsetWidth` 不足以证明未裁字。
7. 切换字号、方向、字体后题签马上重新包住文字；不留下上一字体的宽高或上一方向的切片。
8. 透明度滑块只影响背景/装饰，不同时让文字变透明。
9. 视觉上可将阅读衬底与装饰层分工，但不是要求改写原 PNG 或新增透明度控件。现有用户透明度含义保持可理解；不要为了对比度偷偷锁死其自定义值。
10. 在浅/深/高纹理背景上检查底色稳定性。标签显得重时优先减弱边框、阴影和装饰，而不是把背景全部变透明造成字看不清。

### P3-03｜预览区域完整、真实，但不变成另一款编辑器

**推荐实现：** 预览使用共享组件、`scale=1`，文案改成“基础比例预览；照片中随显示尺寸缩放”，不继续将它标成并不成立的“实际比例”。这是为避免预览尺度误导，不改变照片中的缩放合同。

1. 不使用固定 94px 高度加隐藏溢出来截断长竖牌。预览区高度随普通姓名适度增长，并在面板可用空间内设上限。
2. 对 1—8 个汉字及普通姓名+别名，整块题签连同底板边缘都要可见；说明文案与题签不叠在一起。
3. 超长名字达到预览上限时允许区域内滚动/明确的适配显示说明，不静默裁切，不以删字符解决。
4. 从当前照片中使用统一状态解析选择有效示例；只有别名也能被选中；显示内容服从当前别名模式。无已命名人物时用虚构示例名。
5. 不把预览尺寸写回照片字号；预览容器变化不得触发人物坐标保存。
6. 生产面板可以保留安静的中性背景；浅、深、纹理三种背景至少在 QA 样本页中覆盖，不为验收强加一套新的复杂设置。
7. 本机字体选择弹窗也使用共享预览外观，展示正在试选的字体与当前主题效果；不要保留一个固定黑底、固定字号、与实际无关的第二套预览。

### P3-04｜设置面板与状态反馈

- 保留低频样式面板，不新增独立设置页。
- 主题、文字方向、字号/字体、透明度及位置相关动作的层级清楚；“恢复外观默认”和“清除本张自定义排版”视觉和文案分离。
- 固定项置灰时能看懂原因，不出现可操作但无效果的控件。小字不能被降成难以辨认的装饰。
- 主题缩略卡应忠实表达主题的字与底，不必放真实姓名；选中状态与实际有效/回退状态同步。
- 焦点可见，Tab 顺序自然，Esc 关闭最上层设置/提示，不误关闭整张照片。
- 宽屏/窄屏都能到达全部设置和底部动作；390px 宽下不产生页面水平滚动、不把按钮挤出可见区域。
- 打开面板、切换主题、关闭面板不导致当前照片位置和 viewer 导航跳动。

### P3-05｜小题签的按需阅读提示

本轮不设固定最低照片标签字号。为兼顾同比缩放与读取姓名，补充一个轻量的完整姓名提示，优先复用现有 hover/focus 引导层，不新增常驻人名列表。

**行为：**

- 已命名标签 hover 短暂稳定后，或键盘 focus 时显示完整姓名；建议普通横排 14px 左右，宽度受视口约束，可换行，文字与别名不截断。
- 提示与已存在的人脸高亮/连接线协调；只显示当前一个，不扩大原标签、不推动其他标签重排。
- 不自动打开人物管理；保留现有单击/双击/拖动区分。没有 hover 的设备仍通过现有点按/管理路径读到姓名，不另改手势合同。
- 鼠标移出、blur、开始拖动、切换照片、关闭查看器或按 Esc 时隐藏，不残留上一张照片的名字。
- 用安全文本写入，不把姓名当 HTML。保留或改善可访问名称；使用自定义提示时避免同时弹出重复的 native title。
- 提示、连接线、焦点框、拖动状态不进入最终照片导出快照。

这是有范围的阅读辅助，不是新增一套“可读模式”，也不能替代普通显示尺寸下的字体与对比度精修。

### P3-06｜视觉验收方法

1. 使用 P0 固定的同一组照片：明亮平整背景、暗背景、高纹理背景、单人近景、普通小合影、拥挤多排合影、竖幅照片、接近边缘的人脸。
2. 在前三类代表性背景上逐一显示四主题，得到至少 12 张可比较的完整查看器截图；其他样本补足排布与边缘情况，不要求穷举所有组合。
3. 另补暗朱混合中英文、素笺长竖名、茶棕三种字体、预览/实图同倍率、窄屏面板、手动位置、资源回退等重点截图。
4. 每张先确认照片、主题、字体、方向、倍率和浏览器状态正确，再保存；空白、加载中、错误页面和旧分支截图必须重拍。
5. 同时查看完整照片的 100% 截图与局部原始像素裁切。局部放大只能佐证笔画/切片问题，不能代替整张照片是否被标签抢占的判断。
6. 给每个发现写“样图编号→现象→修改→复拍→结果”。不能只说“更高级”“明显更好”。
7. 对默认参数下的代表样图，可记录文字与合成背景的对比度，内部目标可采用 4.5:1；必须考虑半透明底板与照片合成后的颜色，不拿原始色值直接冒充结果。这个目标不是对全部照片、任意透明度和所有缩小尺寸的合规保证。
8. 有意选择极低透明度的用户自定义，不强制覆盖；如不可读，在报告标为自定义边界。默认主题参数在代表样图上应有清楚的姓名阅读效果。
9. 合影中以“能清楚分辨姓名属于谁”为必要条件。标签本身精致但靠到另一个人旁边，不算通过。

**P3 出口：** 四主题同图比较、关键细节截图与复拍闭环完成。没有真实底板或浏览器能力时，只能交付代码/合成样本验证，不能把 P3 标为通过。

## 8. P4：端到端回归、故障注入与导出一致性

### P4-01｜手动位置必须经得起保存、失败和切图

位置测试全部在隔离服务和隔离数据中完成，不能用正式照片的手动位置做试验。

**逐步测试：**

1. 打开隔离照片 A，确认其最初的自动模式和已保存坐标。拖动一块标签到可识别的新位置；检查实际发送的照片 ID、人脸 ID、归一化坐标及成功回执。
2. 重开 A、刷新页面、改变窗口尺寸，检查标签中心的相对位置仍正确。因标签尺寸变化而发生的边界夹取应有明确规则，不能把夹取后的显示坐标自动回写为新的用户坐标。
3. 将 A 从自定义切到智能、左/右/上/下等当前已有布局，再回到自定义；保存坐标必须未被清除。监听网络确认这些切换没有触发清除或位置写入接口。
4. 调整主题、字体、字号、方向和别名显示；这些动作可以改变标签尺寸并重新布局，但不能偷偷重存手动坐标。
5. 连续拖动同一标签三次，在测试服务注入不同响应延迟。保留既有写队列、operation ID 和 revision 约束；最终界面与服务端都应是最后一次有效操作，不能被较早回执覆盖。
6. 拖动后立即切到照片 B，让 A 的保存请求延迟返回。B 不得被改动、重排为 A 的数据或显示 A 的错误提示；再回到 A 时，显示其真实已保存结果。
7. 对最近一次保存注入失败，检查标签恢复到正确的已提交位置，且有一次清楚提示。不能回到另一张照片的位置，也不能因失败丢掉此前成功保存的坐标。
8. 在 pointercancel、未超过拖动阈值的点按、双击、拖动后释放等路径下检查：取消不保存；点按不误拖；拖动不误触命名/管理；现有点击和双击行为保持。
9. 有待提交位置时点击“清除本张自定义排版”：确认清除与保存的先后关系，不出现清除后旧请求又把位置写回的竞态。测试应覆盖执行中切换照片，不能清错对象。
10. 清除成功后只清除 A 的手动坐标；照片 B、人物姓名、别名、人物归属、人脸框及缩略图都不变。清除失败时不假装成功、不清空本地真实状态。

**实现边界：** 优先复用既有写入队列与实体会话，不新增平行的保存系统。不因为页面关闭就粗暴清空所有 pending 容器，导致仍在进行的合法写入失去归属。若确有竞态，只修当前标签链路，并增加可重复测试。

**验收证据：** 脱敏的操作序列、请求与回执顺序、坐标前后值、失败注入方式。只展示拖动后的截图不足以证明“保存正确”。

### P4-02｜导出的标签不能落后于屏幕上的标签

先查实际导出实现，再适配。参考版本存在冻结快照、资源白名单、原图渲染及相关测试；不要假设只改照片 CSS 就会自动覆盖导出。[S6]

**实施与测试步骤：**

1. 查明导出快照从哪个 DOM 捕获，收集哪些样式文件、根变量、主题属性和字体，以及哪些控制元素会被排除。
2. 若新增共享 CSS/模块，确保导出能取得相同视觉规则。不能让浏览器加载新 CSS，而导出仍只加载旧的 `viewer-overrides.css`。
3. 在当前照片和标签已稳定、所需字体与底板已就绪时捕获快照。记录对应照片、标签内容、实际有效主题、字体和坐标；等待期间发生切图必须重新核验或明确取消，不能混用两个时点。
4. 快照一旦冻结，后续渲染不重新做另一套自动排布，也不读取稍后更改的偏好。不能把“导出时优化位置”变成屏幕和成片不一致。
5. 使用原图作为导出照片源，保持当前导出尺寸、格式选择、文件命名和底部签名合同。不得为通过测试而将导出改为简单截屏或低分辨率预览图。
6. 四款主题各完成至少一次实际导出，其中包含：中文竖排、英文横排、姓名+别名、已有手动位置。至少一张同时含中英文标签。
7. 再验证关闭人名显示时的导出，以及当前已有的默认格式和可选格式。关闭姓名不应被导出逻辑重新打开。
8. 图片中不得残留本轮新增的阅读提示、设置预览、操作面板、焦点环、拖动状态和连接引导线。底部照片签名等原有成片信息不能误删。
9. 比较成片与快照中的姓名内容、实际字体、有效主题、方向、留白、边角和位置。按输出尺寸折算坐标后比较；不要拿原图分辨率的导出像素与屏幕 CSS 像素直接相减。
10. 仅对隔离样本的源文件做前后 hash 核对；应完全相同。所有导出写入隔离输出目录，不覆盖源文件、不回写 EXIF。

**比较方法：** 优先用无损格式检查几何与装饰，允许同一字形的栅格化存在小差异；JPEG 的压缩差异不能直接解释为样式错误。标签在屏幕坐标系中的等效边界/中心差异通常应在 1 CSS px 内；若现有导出管线有确定的取整误差，记录公式和实测值，不能笼统放宽为“差不多”。

**安全门：** 既有快照 HTML、CSS、文件路径和请求来源白名单不能放宽。不得为支持新组件而允许任意文件、任意 URL、任意 script 或服务端外网访问。自定义本机字体若现有导出进程确实无法取得，保留可读回退并明确告知实际导出字体，不能静默宣称与界面完全相同。

### P4-03｜异步与故障不是最后临时看一眼

使用隔离浏览器的请求拦截或测试服务完成以下注入，不能修改正式资源文件制造故障：

| 情形 | 具体动作 | 合格结果 |
|---|---|---|
| 冷缓存字体 | 新 browser context，延迟当前主题字体响应 | 初始可读；字体就绪后只对当前照片重新测量；不残留旧坐标、无无限重排 |
| 仅横版底板缺失 | 让 7.png 或 8.png 返回失败，竖版正常 | 识别资源不完整并一致回退；不是只有英文标签裸字/空底 |
| 全部底板缺失 | 阻断四张图片 | 可用的默认主题继续显示完整姓名；用户主题意图不被永久抹掉 |
| 图片可响应但不可解码 | 返回损坏的测试图片 | 不能仅凭 HTTP 200 标可用；进入有界的故障处理 |
| 失败后恢复 | 解除拦截并触发规定的重试/重开路径 | 可恢复原主题，不因缓存失败 Promise 永久锁死 |
| 快速主题切换 | 字体尚未加载时连续切换四主题 | 最后选择生效；旧回调不能把主题切回去 |
| 快速切图 | A/B/C 加载交错，包括慢图 | 标签始终属于正在显示的照片；旧结果不能污染新页面 |
| 持久化不可用 | 测试 profile 中注入存储失败 | 当前会话仍可使用，有克制提示；不清空其他设置，不反复弹错误 |
| 损坏偏好 | 注入无效 JSON、数组、未知主题、非法数值 | 使用经过校验的回退；无 NaN/Infinity/undefined 进入可见文本或坐标 |
| 自定义字体权限拒绝 | 拒绝权限或在不支持的环境打开 | 解释限制，可取消回到正常面板，不假装选择成功 |
| 查看器关闭 | 字体/位置/照片请求未完成即关闭 | 不把关闭的查看器重新打开、不残留 tooltip、不持续创建观察器 |

预期注入的失败应在测试报告中标记；“没有 console error”不能通过吞掉全部错误实现。正常路径无新增未处理异常；故障路径应有可解释的有限日志/用户提示。

### P4-04｜性能与焦点稳定性

本任务不要求重写智能排布算法，也不以“性能优化”名义减少人名或降低约束。

1. 构造包含 1、6、20、50 张人脸的隔离数据集，固定图尺寸、字体、主题、浏览器和窗口。50 张脸是压力情形，不要求数学上不可行的布局无条件达标。
2. 分别记录基线与修改后：一次稳定渲染/重排耗时、主题切换稳定耗时、缩放时重排次数。先预热，再至少测 20 次，报告中位数和 P95。
3. 常用 6/20 人场景不应出现可感知退步。内部排查触发线可设为 P95 比基线增加超过 `max(8ms, 基线的20%)`；这是本任务的排查线，不是外部标准，也不允许据此忽略明显卡顿。
4. 连续打开/关闭查看器、切换主题或调整窗口 30 次，确认监听器、观察器和 pending 状态没有明显累积；不要求拿一次堆大小变化就作内存泄漏结论。
5. 字号滑块的多次 input 应合并到合理渲染节奏，不为每个事件同步重复读写整层 DOM。停止拖动后以最后值稳定显示。
6. 重新排布不能把用户正在操作的面板控件移走、清空输入或使键盘焦点无故回到 body。被聚焦标签确需重建时按稳定 face ID 恢复焦点；照片已切换则不能恢复到别人的标签。
7. 不为了让测试数字变小而修改测量边界、关闭重排、排除慢样本或把测量移动到异步任务之外。

### P4-05｜相邻功能只回归，不顺手重构

至少检查：大图打开/关闭、上一张/下一张、缩放与拖动照片、显示/隐藏人名、别名切换、资料抽屉开关、底部签名切换、标签管理弹层、已命名/待处理/路人高亮、从人物视图返回原浏览位置，以及导出。

这些功能若因本次改动回归，必须修复；若发现基线已有且与任务无关的问题，记录为独立事项，不扩大本轮范围。不能因为要测标签而重做首页、地图、扫描流程或人物合并。

**P4 出口：** 写入/回退、资源故障、导出、性能与相邻功能都有实际结果。测试脚本通过但真实视觉缺失，或四主题之一缺素材，不能写“整体全部通过”。

## 9. 本地执行方法、测试层级与阶段门

### 9.1 命令使用原则

命令必须由执行 Agent 结合实际系统、解释器、端口和脚本入口确认后运行。不要复制历史报告里的机器路径，不假设每个 Python 文件都可直接执行，也不假设每个脚本支持 `--base-url`、`--data-dir`。

可先执行以下只读检查；输出中若含私人路径或凭据，只存本地、不得直接放进公开报告：

```text
git status --short
git branch --show-current
git rev-parse HEAD
git remote -v
git worktree list
```

源码搜索可使用仓库现有工具或 `git grep`，例如：

```text
git grep -n -E "faceHasUsableName|namedFaces|faceLabelText|faceLabelPosition|faceVertical|faceAlias" -- web validation
git grep -n -E "face-name-layer|is-horizontal|face-style-preview|face-label-bg" -- web validation
git grep -n -E "PHOTO_LIBRARY_DATA|PHOTO_WEB_ROOT|FACE_LABEL_DIR|face_labels_available" -- app.py ourtime_config.py validation
```

这些只是定位入口，不构成完整引用分析；模板生成、动态调用、快照、测试解析和导出仍需检查。

### 9.2 先建立可证明安全的聚焦测试入口

若现有聚焦入口已能正确隔离，直接复用。否则新增一个小型、可重复的标签测试入口，至少具有这些约束：

- 明确接收或集中声明测试数据目录、测试代码目录、测试服务 URL 和输出目录。
- 在任何初始化、写请求、删文件或启动进程之前校验目标不是正式目录/正式服务。
- 不使用正式浏览器 profile；不把全局环境变量长期改成测试值；子进程配置与主环境分开。
- 仅创建合成数据或使用已准备的少量隔离图片；不触发正式扫描或模型加载。
- 记录启动 PID，只结束自己创建的服务；端口占用时退出或选安全空闲端口，不杀占用者。
- 分别输出“单元测试、DOM 行为、浏览器截图、导出、性能”的状态，不能以一个总 exit code 掩盖跳过项。
- 发生缺素材/浏览器失败时给明确原因，不自动把失败改为通过。

**不要为了测试搭建新平台。** 优先复用项目现有 Python、Node、Playwright 等工具；只有已有工具不能覆盖目标时才增加必要的小脚本。不得升级全项目依赖或新增前端构建链。

### 9.3 分层验证，不每次全库跑一遍

| 层级 | 运行时机 | 证明什么 | 不能证明什么 |
|---|---|---|---|
| 静态/语法 | 每次小批改动后 | 文件可解析、引用/入口无明显缺口 | 真实布局、字体、保存、导出正确 |
| 纯逻辑用例 | P1 起持续 | 状态真值表、方向、缩放、迁移、资源状态转移 | CSS 与真实图片的组合效果 |
| 聚焦浏览器 | P1/P2/P3 各出口 | 实际应用入口的事件、DOM、尺寸、图片与字体加载 | 正式库所有照片均无问题 |
| 写入与故障 | P1/P4 | 隔离服务中的坐标保存、失败回退、异步归属 | 正式服务已经升级 |
| 视觉截图 | P0/P3/P4 | 同一固定样本上四主题及边界的实际效果 | 单靠截图证明存储一致性或全面可访问性 |
| 导出回归 | P2 涉及组件之后、P4 最终 | 屏幕快照与成片同源，原文件不变 | 仅由 API 返回 200 推定图片正确 |
| 项目 smoke | 按现行 AGENTS 约定 | 静态防呆与它实际访问到的接口状态 | 不能把正式旧服务的通过当作新分支通过 |

`python validation/smoke.py` 是仓库当前说明中的日常入口，但执行前仍要确认当前版本的读取/网络行为。存在正式扫描忙碌等条件时，保留明确 SKIP 原因；该 SKIP 不替代本任务的隔离浏览器和写入验证。

涉及后端资源解析或导出代码时，运行相应聚焦后端测试。只有达到现有项目说明中的触发条件，才跑完整 `validation/validate.py`；不要为了完成感运行扫描/恢复/合并全套无关工作流。

### 9.4 五个明确阶段门

- **G0：** 基线、隔离、素材清单、缺陷复现和旧测试风险已经记录。未满足前，不实施生产相关操作。
- **G1：** 状态、恢复默认、方向、偏好及资源逻辑通过聚焦用例；没有位置数据破坏。通过后进入组件统一。
- **G2：** 共享组件真实接入，预览/实图规则同源，删除台账完整，基本导出未断。通过后做视觉细调。
- **G3：** 四主题实际样图与关键细节复拍完成，裁切/边框/字体/方向问题闭环。缺素材或截图即不通过该门。
- **G4：** 完成第 10—11 节的硬性用例、导出与隐私检查，报告真实状态，形成可审阅提交。

阶段门是 Agent 自检条件，不是要求用户每一阶段回复“继续”。范围内问题自行修复；无法安全继续的部分按第 13 节处理。

## 10. 验收矩阵：必须执行的情形和判定口径

以下是最低用例集合，不要求把所有维度做笛卡尔积。优先在同一稳定浏览器环境完成核心矩阵，再补窄屏、缩小比例和故障边界。每一行必须有真实状态：`PASS / FAIL / BLOCKED / SKIP / NOT_RUN`，并附证据。

- `PASS`：对应行为按预期执行，证据存在。
- `FAIL`：实际执行但与预期不符；需修复后再跑。
- `BLOCKED`：缺少必要素材、环境或权限，不能执行；写明缺少什么。
- `SKIP`：根据本卡条件确实不适用，如环境不提供某一可选自定义字体能力；不等于通过。
- `NOT_RUN`：尚未执行；不能藏在总通过率里。

### 10.1 基线与安全

| 用例 | 操作 | 必须达到的结果 | 主要证据 |
|---|---|---|---|
| FL-001 | 核对 repo、HEAD、分支、已有 dirty 文件 | 使用正确项目，不覆盖用户已有修改 | 版本表、原改动清单 |
| FL-002 | 核对正式静态目录与任务 worktree | 任务改动不直接进入正式静态目录 | 目录关系与文件差异说明 |
| FL-003 | 启动隔离服务并读取其身份 | 数据/代码/输出均隔离，不只端口不同 | 解析后配置与服务身份 |
| FL-004 | 运行脚本前检查其实际 URL、数据库路径和导入副作用 | 不盲跑硬编码正式库/正式地址脚本 | 测试入口审核清单 |
| FL-005 | 检查待提交文件和忽略规则 | 私人样图、名字、路径、存储和字体未被提交 | staged 文件清单、忽略核验 |

### 10.2 人物状态、文字与偏好

| 用例 | 输入/操作 | 必须达到的结果 |
|---|---|---|
| FL-010 | 普通姓名、无别名 | 各入口认作同一个已命名状态；显示完整姓名 |
| FL-011 | 姓名空、只有别名 | 统计、照片、预览、管理入口一致按已命名处理，不显示未命名“＋” |
| FL-012 | 只有历史占位名、无有效别名 | 依现行占位合同为待处理，不拿占位字当正式姓名题签 |
| FL-013 | 占位名+有效别名 | 以有效别名形成可用显示名，各处一致 |
| FL-014 | 名字包含占位词但不是占位词本身 | 不误判，例如不能通过字符串包含关系抹掉合法姓名 |
| FL-015 | ignored=true/1 与 ignored=false/0 | 路人状态优先，恢复后状态按现行数据重新解释 |
| FL-016 | 空白、null、字段缺失、合同允许的序列化布尔值 | 不报错、不出现字符串 undefined/NaN；不把字符串“0”误认作 true |
| FL-017 | off/with/only 三种别名模式 | 显示规则、预览与管理提示一致；姓名与别名相同不重复拼接 |
| FL-018 | 显式传入模式与全局模式不同 | 被测纯函数服从显式参数，不能暗中重新读取全局 |
| FL-019 | 同人物多脸、不同人物同名 | 人物统计按人物 ID 的既有口径；不能按姓名文本合并人物 |
| FL-020 | 旧 faceAlias=true，但新 faceAliasMode=off | 新字段优先；刷新后仍是 off |
| FL-021 | 合法新方向、旧方向字段及无版本旧设置 | 按明确迁移表处理，后续用户选择不被反复重置 |
| FL-022 | 旧 outline / ink / paper / cinnabar 等主题设置 | 保留必要迁移，输出稳定；连续读取/保存不反复变换 |
| FL-023 | 合法主题的用户自定义参数 | 除非法值或现行主题限制外，不擅自重置为全套默认 |
| FL-024 | 恶意/损坏 JSON、未知 theme、越界数值 | 安全解析、有限回退，不让任意值污染 DOM/CSS |
| FL-025 | 更改字号/主题→恢复外观默认→刷新 | 默认正确恢复并持久化，样式与排布更新 |
| FL-026 | 恢复外观默认时已有手动位置、别名模式、方向和播放间隔 | 只恢复约定的外观及标记；其他状态不误清 |
| FL-027 | 在隐藏人名时切换主题/恢复外观 | 设置正常更新，但人名不被偷偷打开 |

### 10.3 方向、字体、底板和组件统一

| FL-055 | 普通小合影和拥挤但可排布的固定样例 | 标签重叠≤5%，单脸覆盖≤35%，估算眼部无覆盖 |
| FL-056 | 右侧外缘人物且外侧有空位 | 可合理向右贴近所属人物，不为统一向左而挤入邻脸 |
| FL-057 | 竖幅、边缘人脸、资料抽屉打开、照片平移 | 坐标基于实际显示图；不会漂到边框/签名/另一张脸 |
| FL-058 | 已证明空间不足的压力样例 | 不伪装达标、不隐藏姓名；显示真实诊断和调整途径 |
| FL-059 | 重复相同输入、窗口与字体进行重绘 | 结果稳定，不因异步/遍历顺序随机跳动 |
| FL-060 | 实际 DOM 测量与算法内部矩形对照 | 检查用户真正看到的标签边界，不能用虚增矩形面积稀释重叠率 |

**几何判定统一口径：**

```text
标签间重叠率 = intersectionArea(labelA, labelB)
               / min(area(labelA), area(labelB))

单标签对某脸的覆盖率 = intersectionArea(label, face)
                       / area(face)

估算眼部覆盖 = 按当前规则构造眼部区域后的实际交集
```

使用最终绘制坐标与实际视觉标签边界，不先把比例四舍五入到一位小数再判断。只允许极小的浮点数 epsilon（如 1e-6），不能把 5.4% 显示成“约 5%”后通过。悬停阅读提示与扩大点击命中区域不计作照片题签的视觉边界；它们也不能遮蔽题签实际冲突。

手动布局允许尊重用户有意设置的重叠，但必须真实诊断，不能给不符合约束的手动位置标 `layoutValid=true`。无可行排布的压力样本是“诊断行为通过”，不是“几何排布通过”。

## 13. 阻塞、恢复执行和回滚规则

### 13.1 这些情况必须停止受影响的操作

| 发现 | 立即动作 | 仍可安全继续的工作 |
|---|---|---|
| 测试指向正式数据或静态目录 | 不执行写入/启动；只终止自己已创建的误配测试进程 | 源码只读审查、纯函数测试、修正隔离设置 |
| 相关文件含无法区分的用户未提交改动 | 不覆盖、不自动回滚、不擅自提交 | 在独立副本比较，记录冲突位置 |
| 真实底板缺失 | 不生成替代图冒充原主题，不删除该主题 | 默认主题、状态/回退逻辑、合成组件测试；对应视觉/导出标 BLOCKED |
| 无浏览器执行或截图能力 | 不把静态检查写成视觉通过 | 代码和纯逻辑测试，保留浏览器用例及待验证项 |
| 缺少真实样图 | 不用漂亮的合成图声称真实合影验收通过 | 合成几何/功能测试；真实视觉标 BLOCKED |
| 需要扩大白名单或允许任意本机文件才能导出 | 不放宽安全约束 | 分析最小资源接线方案或保留已支持回退 |
| 必须改人物识别、合并或库结构才能继续 | 不自动扩大范围 | 完成本轮独立标签修复，记录具体依赖与影响 |
| 正式扫描在运行 | 不停止/重启/改参数，不做全库只读压力测试 | 独立合成数据的开发与验证 |

阻塞只影响依赖它的工作，不是停止全部任务的借口。例如真实茶棕底板缺失，不妨碍修复“恢复外观默认”或偏好迁移；但仍然不能宣布四主题完成视觉验收。

### 13.2 防止上下文变长后退回“只写计划”

每阶段结束，在本地更新一个简短 checkpoint，包含：当前阶段、已改文件、已通过用例、未完成项、测试入口、分支和私有证据位置。不要重复复制完整任务卡到每个日志。

恢复执行时先读任务卡、checkpoint、当前 diff 和实际测试结果。重新核对服务/目录身份，不沿用上一进程的 PID 或假设端口仍属于自己。已经通过且未受后续修改影响的测试可以复用；受改动影响的测试必须重跑。

### 13.3 回滚顺序

1. 明确回滚目标是本轮代码变更，而不是用户数据。
2. 停止且只停止本次创建的隔离测试进程，保留失败日志和最小复现。
3. 在独立任务分支按明确提交回退，或恢复本任务自身的已知安全检查点；不用全局 `reset --hard` 抹掉其他工作。
4. 若需要删除隔离生成物，先确认路径确实位于本任务隔离区；不使用包含未知变量的递归删除命令，不触碰正式素材。
5. 如果曾在后续明确授权下部署，按当时记录的部署文件清单与版本恢复，先确认没有新用户改动；本卡不提供自动生产回滚授权。
6. 不为回滚界面修复恢复整库，不清除浏览器全部 localStorage。偏好迁移保持可兼容；必要恢复只针对本任务明确备份的那个偏好键，且不得覆盖后续用户选择。

### 13.4 给用户的最终状态必须分层

合格的状态描述例如：

```text

功能：状态、恢复默认、方向、坐标保存与故障回退通过。

导出：四主题实际成片核验通过，源文件 hash 不变。
远程：未推送。
正式服务：未部署、未重启、未执行测试写入。
剩余：列明实际剩余项；没有则写无，不用空泛限定语。
```

上述仅是报告样式，不是预置结果。某一层未完成，直接写未完成及原因，不用其他层“通过”来抵消。
