## 已确认的源码机制

| 场景 | 源码证据 | 影响 |
|---|---|---|
| 首页切类别 | home-discovery.js 的 loadHomeDiscovery 请求前用 loading HTML 替换整个 board | 原卡片与高度立即消失，接口返回再建卡片，图片另行加载；缓存只存一个 payload，返回别的类别仍会重走流程 |
| 换一组 | board 加 is-updating，CSS 将全部子项 visibility:hidden，再下一帧 render 整板 | 局部换组触发整个推荐板刷新，重新创建无关图像节点 |
| 类别“查看更多” | 请求携 cursor，返回后覆盖 payload，再重建 board；没有追加旧 items | 当前实现更像换页而非查看更多，可能让用户失去原列表和阅读位置 |
| 普通页面进入 | preparePanel 加 is-switching；appearance.css 设 opacity:0、translateY(2px)，120ms 后 is-pending 变 .55，完成再 reveal | 一次切页可能经历消失、半透明、恢复；叠加照片网格 .55 状态，变化更多 |
| 照片流切换 | resetPhotoStream 清节点且 height=0；loadPhotos 有保高逻辑，但此前清空后不能保住原高度；另有 oldTop<0 时强制 scrollTo | 文档高度收缩可能触发浏览器滚动钳制，然后再次主动滚动 |
| 返回页面 | continuity restore 先 await setView，再 restorePosition；setView 已调用 revealPanel | 存在先显示顶部再跳到原锚点的时序风险，需逐帧验证 |
| 进入大图/翻图 | setViewerLoading(true) 立即显示 indicator；CSS indicator inset:0、z-index:80、background:#101411 | 整个显示区域被不透明深色罩层遮住，不只是一个加载文字，即使已有上一张照片可保留 |
| 首次进入大图 | openPhoto clearViewerImage 后先 showDialog，再等待 displayPhoto | 先打开空大图容器，再等图片；初始过场缺少同一照片缩略图承接 |

displayPhoto 已有“新图片 decode 后再提交可见状态”的保护，应保留，不能为流畅改成图片与姓名/地点不同步。

## 修改任务卡

目标：各层切换不露错误内容、不整屏闪白/闪黑、不反复回顶。保留已有查询、快照和撤销业务；不做新一轮布局改造，不改正式库，不重启正式服务。

### 1. 先做真实基线

检查当前 AGENTS、dirty diff、被测前端实际响应。浏览器连接恢复后按下方路径逐条检查，用短录屏或连续帧捕捉点击后 0–1000ms，单张最终截图不能证明不闪。

记录 CSS 视口、缩放、滚动起点、请求时长。区分冷缓存和重复访问；必要时只在隔离环境人为延迟相关响应至约 600ms，证明慢请求也不会暴露错误内容。不改变用户浏览器持久设置。

### 2. 首页分类与局部刷新

- 标题、类别条和页面宽度保持稳定。快速切换不先清空整个 board。
- 缓存按类别和有效数据版本分开，不只保留最近一个 payload；缓存命中保留已有 DOM，失效时重新请求，不引入永久陈旧结果。
- 请求中保留旧画面的高度与内容，但标记繁忙并阻止误操作；不得把旧类别卡片当作已加载的新类别。可将选中状态的提交延后至新内容可用，或明确局部更新态。
- 建议超过 180–250ms 才显示小范围等待提示，快请求不闪一次文字。提示出现与消失不改变占位尺寸。不人为拖慢快响应。
- 首次无内容时使用与目标卡片结构一致的静态占位，不用高度明显更矮的一行“加载中”。避免全屏 shimmer。
- 新卡片尺寸先保留，首屏图像预加载/解码后再交换；有超时和坏图出口，不能等待所有图片而卡死页面。
- 换一组只替换对应卡片，其他卡片 DOM、图片、位置保留；隐藏卡片也按最小范围更新。移除整板 visibility:hidden 方案。
- “查看更多”应追加且去重，保留已显示项目和阅读位置；若产品想要换页，必须改成明确下一页并保持固定顶部，不能按钮叫查看更多却丢掉旧内容。
- generation/AbortController 覆盖快速来回切换，迟到响应不得覆盖当前页；已进入缓存返回路径也要取消或隔离旧请求。

### 3. 普通分页与推荐详情

- 明确一次导航的 pending、ready、error 状态，避免页面透明、网格变淡、中央提示同时叠加。
- 保留壳层和待显示区域高度，移除“完全消失→半透明→恢复”的强制三段效果。不要通过全局取消所有动画伤及地图和大图专用交互。
- 不同照片集合切换时旧数据不能被误点击为新集合；准备好新集合再一次提交，或者展示对应高度的中性占位，不能把旧标题与新照片混搭。
- 返回缓存页：先校验范围和锚点，布局及滚动恢复完成后再呈现。无效锚点退回合理起点并提示更新，不能多次 scrollTo 相互纠正。
- 不对所有导航统一 scrollTo(0,0)。首次进新列表和返回旧列表有不同滚动策略。
- 出错/快照过期使用稳定区域内的重试或返回入口，不闪“没有照片”，不静默切全库。

### 4. 大图进入、翻图与关闭

- 首次打开：用点击的同一张缩略图承接大图舞台，尽量锁定正确比例，高清图 decode 后原位替换；缩略图不可用时有稳定中性底色，不露上一次照片。
- 翻图：已有照片可保留到新照片准备好，取消每次立即覆盖全幅不透明黑色加载层。超出等待阈值时，在固定角落显示小提示即可。
- 等待期间保持原照片对应的人名、日期、地点；新图及其资料一起提交。写操作继续禁用或绑定实际显示对象，保留现有 request token 保护。
- 图像失败保留正确的上一张及错误反馈，位置编号不要提前假装已经翻到成功的新图；首次失败给返回/重试出口。
- 关闭：先准备底层列表和目标位置，再撤去大图；不得关闭后先闪列表顶部再滚动。
- 动效默认可以没有；若确有必要只做约 100–150ms 的轻微透明度变化，不额外滑动整页或缩放舞台，尊重 prefers-reduced-motion。

### 5. 逐项走查清单

| 路径 | 观察重点 |
|---|---|
| 综合→今日→地点→人物→综合 | 顶部稳定、类别正确、无清屏闪烁；各走冷/暖两次 |
| 类别查看更多，随后返回 | 内容确实追加；不丢旧项目、不回顶 |
| 综合换今日/地点/人物其中一组 | 无关卡片不重载、不隐藏 |
| 三类推荐各进组详情再返回 | 加载提示与标题正确，回原卡片；各含一组多页内容 |
| 详情滚到中部→大图→下一张→关闭 | 无黑色遮挡闪烁；回刚看照片而非顶部 |
| 大图下一张/上一张快速连点 | 图、名字、地点、序号一致，迟到响应无污染 |
| 首页↔全部照片↔文件夹↔人物↔地点↔合影↔收藏 | 顶栏不跳、旧页内容不串、新页不误报空态 |
| 地点进范围列表/人物进相关照片/合影进分组 | 查询范围保持；不为消闪牺牲原导航 |
| 浏览器后退/前进与页面刷新 | 恢复发生在呈现前；失效有明确降级 |
| 延迟、失败、空结果、409 过期 | 不无限等待、不闪错文案，重试可用 |
