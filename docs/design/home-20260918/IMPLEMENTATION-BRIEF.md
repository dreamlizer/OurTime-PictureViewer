## 4. 首页页面与交互规格

### 4.1 第一张设计如何落地

- 桌面保留侧栏，增加“首页”并正确高亮。全部照片及其他现有入口继续可用。
- 主体上方是“首页”和真实本地日期。日期、星期必须来自同一日期计算，不复用图片中的示例。
- 标题下可有紧凑的四个类别选项；不做大面积统计数字或功能介绍。
- 综合页上半部：主照片在左，事实标题、数量和进入按钮在右；左右约 60:40。下方地点与人物两栏。
- 浅绿侧栏、近白背景、深绿重点色；可参考 #eef2ef、#f7f8f6、#285c49，优先兼容项目已有色彩变量。
- 使用项目现有字体与本地资源，不为首页下载在线字体或引入 UI 框架。标题有层次，正文保留可读性。
- 主封面优先横向图。无合适横图时允许留底色完整展示，不把竖图严重裁切成难辨内容。人物拼图优先用已有脸框定位裁切或真实照片，不拉伸、不生成人脸。
- 图中诗意故事、假人名、示例日期、版本号均不得进入真实页面。事实说明示例为“2018 年 9 月 18 日 · 杭州 / 24 张照片”，地点不一致则省略单一地点。
- 主推荐缺失：可以把有内容的地点或人物提升至主区域，明确显示真实类别；不能仍挂“往年今日”的标题。
- 390px 窄屏改为单列，沿用现有移动导航，图片与文字上下排；类别选项换行或紧凑排列，整页不得横向溢出。

### 4.2 明确每个动作

| 动作 | 结果 |
|---|---|
| 点击组封面、标题或主按钮 | 同一个组详情列表，展示完整集合，标题、数量、返回首页入口可见 |
| 点击人物年份预览 | 第一版仍进入该人物组列表；不引入另一套大图直达逻辑 |
| 点击类别 | 切换类别及独立分页，记录该类别状态 |
| 换一组 | 同类别选下一候选，只替换该位置；无其他候选则提示“暂时没有更多”，不无限转圈 |
| 暂时不推荐 | 隐藏当前组，补入同类候选；提供即时“撤回”及首页更多菜单内“恢复暂时隐藏的推荐” |
| 返回首页 | 恢复原类别、已换过的组、分页和卡片位置；键盘焦点回到来源卡片或最近可用入口 |
| 返回全部照片 | 明确切换到 timeline，不携带隐藏的推荐组条件 |

卡片内部换组、隐藏按钮应阻止冒泡；按钮支持键盘与可见焦点。加载占位不显示“没有照片”；空数据、网络错误、接口不支持是不同状态。失败显示重试和全部照片入口，不伪装为空库。

## 5. 推荐规则：先定义集合，再选封面

### 5.1 所有推荐共用资格

- asset 未排除，至少有一行 files 同时未排除且 exists_now=1。不逐文件 stat，不读取原图做推荐分析。
- 排除已标记 `截图`、`小图 / 素材` 的类别。尺寸不明不因此臆断是小图；不新增图像分类扫描。
- 依据 asset_id 去重，不因 files 或 faces 的多行 JOIN 放大数量。
- 候选、卡片数量、列表、序列必须使用一致资格。普通图库的筛选语义不应因此被全局修改。
- 照片的 effective date 以有效人工日期优先；人工日期为空按项目既有语义处理，先测试 NULL 与空串。人工日期只有年/月时，不退回精确 EXIF 冒充人工指定的日期精度。
- 人工日期存在但无法解析为准确日时，不参加今日/连续日期分段。允许在其他合适入口显示原有文字，不能编造具体日期。
- EXIF 的可信来源和精度值以元数据读取器实际写入格式为准。文件名、mtime、入库时间不能用于“往年今日”。拍摄日期取记录中的本地拍摄日，不无依据做 UTC 日期平移。

### 5.2 往年今日

1. 使用服务器本地日历日期，接口返回该日期及生成时间；测试提供可注入时钟，不改系统时间。
2. 只选年份小于当前年、月日完全相同、可信且精确到日的照片；每个年份一天是一组。
3. 有同日组时优先同日组；没有时选往年同月，按年份月份分组，改称“那年这个月”。月份组允许可信且精确到月的日期，不能混入仅知年份的数据。
4. 2 月 29 日不映射到其他日期；闰日不存在时按照当日真实候选和月级降级规则处理。
5. 年级数据不在本期另加第四种推荐，避免为了丰富首页无限扩大范围。
6. 同一天多地点可以同组，但标题不声称整组发生在某个地方；有可靠共同地点才加地点副标题。

### 5.3 重访一个地方

1. 第一版使用项目现有完整有效地点值作为分组键，保留完整行政层级；显示可用 prettyPlace 缩短，但键不能截成街道名或末级重名。
2. 人工地点按现有优先级生效。不新做 GPS 聚类；已有可靠归一地点能力可复用，不能擅自将邻近城市并成一组。
3. 只用可信日级日期；同地点按日升序，相邻拍摄日期差不超过 1 天归一段，间隔超过 1 天拆段。一段到第 7 天结束，后续另起段，保证稳定且可复现。
4. 一段至少 3 个有效 asset。日期范围标题取真实最早与最晚拍摄日；不能取补齐的空白日期。第一版只推荐结束日早于今天的片段。
5. 组身份含完整地点键和日期段，推荐详情不得只按 place 查询而遗漏日期条件。资格及稳定成员应按第 7 节处理。
6. 用户手写完全相同但没有行政层级的地点按已有值处理，不扩充成想象的城市；不声称是一次旅行。

### 5.4 人物这些年

1. 人物有非空姓名、非 ignored/路人，排除 suggested_person_id 等尚待确认的候选人物记录；复用当前正式人物判定，先查清 confirmed/reviewed 字段实际含义，不要求每张自动归入的脸都人工 reviewed=1。
2. 只使用正式 faces.person_id 关联，不把建议归属扩成事实。先按 asset 去重，再算数量和年份。
3. 有至少两个可信年份时显示“人物这些年”；只一年或年份不足时显示“与某人的片段”，不虚构跨度。未知日期照片可留在人物组完整列表末尾，不参与年份封面。
4. 组包含该正式人物所有符合推荐共用资格的照片，而非仅封面几个年份；封面最多 4 张，优先最早、最晚及中间分散年份。
5. 人物合并、改名、标路人后，失效旧身份须正确处理；不能把旧 group_id 意外映射到无关人物。

## 6. 封面、稳定性和本机偏好

先有合格集合，再按可解释顺序选封面：预览可用、合适尺寸/比例、收藏优先、时间分散；同级使用稳定 asset_id 或稳定哈希打破平局，不能依赖 SQL 无 ORDER BY 的偶然顺序。

当天候选的排序种子由日期、类别、算法版本和组身份组成。不要使用进程随机 hash 作为跨重启种子。相同输入跨刷新/重启排序一致；偏好变化和数据变更可以令候选失效，但不应无故重排其他有效卡片。

综合页可见封面尽量全局去重。照片不足时减少拼图张数或隐藏重复卡片，不为了填满四格重复同一照片。组内容可以自然重叠，例如同一张照片属于今日与某人物；不删掉组内真实成员。

偏好只记录版本、稳定组标识、类别、隐藏到期日与最近打开时间，设数量上限并清理到期项。不要记录原图路径、人脸特征或全量照片内容。localStorage 失败或禁用时退回本次会话，不让首页打不开。

预览请求失败可在有限备选中换封面；整个组预览不可用时显示可理解状态或换组，禁止反复无限重试。选图过程不在一个请求中触发全库缩略图生成。

## 7. 后端接口与“完整组”合同

以下为建议接口结构，执行者可调整命名，但必须保留语义，并在进度文件写出最终合同。建议新增独立 `home_recommendations.py` 和前端 `home-discovery.js/.css`，避免把所有规则堆入 app.py。

### 7.1 推荐响应

建议 `GET /api/home/recommendations?category=all&cursor=...`，响应至少包含：

```json
{
  "schema_version": 1,
  "as_of_date": "2026-09-18",
  "generated_at": "...",
  "revision": "...",
  "category": "all",
  "items": [{
    "group_id": "稳定的逻辑组标识",
    "snapshot_id": "本次可浏览集合版本",
    "kind": "on_this_day",
    "title": "2018 年 9 月 18 日",
    "subtitle": "24 张照片",
    "photo_count": 24,
    "cover_asset_ids": [101],
    "date_from": "2018-09-18",
    "date_to": "2018-09-18",
    "browse": {"recommendation_snapshot": "..."}
  }],
  "next_cursor": null
}
```

例中数据仅用于解释合同，不得写死成测试之外的产品数据。日期/地点/人物事实也可用结构化字段由前端格式化。只返回有限卡片，不输出文件路径、embedding 或全量成员 ID。

### 7.2 组分页与大图

推荐采用服务端带版本的成员快照：组被打开时生成有限元数据的有序 asset_id 集合，后续按该集合分页；或使用能证明相同语义的固定查询描述。只靠 max_id 不能冻结旧照片的日期、地点、人物修改，不能把 max_id 当作完整快照。

建议让 `/api/photos` 通过一个显式参数识别推荐快照，使 waterfall 与 viewer 的 sequence、around、tail、offset 共用同一数据路径。若使用独立分页接口，必须同时适配所有这些消费点，不复制一套简化大图。

必须保证：

- 有确定排序与 asset_id 次排序，重复翻页无漏项、无重复。
- 列表 total、卡片数量和大图位置来自同一集合版本；不能拿封面数组当组列表。
- 新入库照片不插入已经打开的快照；下次更新推荐再进入。
- 排除、文件全部缺失、人物关系改变等令成员不再符合范围时，以最新有效性为先：使快照明确失效或重建，给出“内容已更新”反馈；不能继续展示已排除内容，也不能静默换全库。
- 无效/过期 snapshot 返回明确的机器错误码，例如 `recommendation_expired`；前端回到原类别提供刷新。非法参数返回 400，未知组 404，版本失效可用 409/410，最终选择写入测试。
- 不接受客户端任意 SQL、路径或无限长 ID 列表。与推荐身份冲突的普通筛选参数应明确拒绝或按文档规则处理，禁止含糊叠加。
- 快照跨刷新与服务重启的存续策略必须明确：可在隔离数据目录内持久缓存，或重启后明确过期；禁止重启后同一标识指向另一个集合。
- 缓存有容量、有效期与算法版本；过期只清本模块缓存，不清用户照片、人工资料、既有证据。

### 7.3 一致性与更新

日期修改、地点修改、人物合并/忽略、收藏、排除/恢复和扫描完成都可能影响推荐。梳理实际写入口，建立明确失效机制。可使用集中数据修订号或 SQLite 可验证的数据变化信号，结合有限周期检查；不能只靠浏览器 toast 触发，因为另一个标签页也可修改数据。

组详情打开和分页前再次核验版本。卡片可短暂保持已渲染的旧布局，但下次激活首页或请求数据时应更新。后台请求合并，缓存重建不长期持写事务、不阻塞扫描。不允许每次首页请求读取所有 embedding 或一次性序列化全库到 Python/浏览器。

## 8. 浏览连续性的具体接入

推荐页状态与普通图库状态分开保存：

| 状态 | 存什么 | 恢复要求 |
|---|---|---|
| 首页 | category、可见组身份、换组位置、分页 cursor、来源卡片 ID、滚动 | 返回不重新抽签；失效卡片选择相邻有效卡片 |
| 推荐详情 | group_id、snapshot_id、排序、列表锚点 asset_id 与偏移 | 先核验版本再恢复，过期不能跳错照片 |
| 大图 | 同一推荐范围、当前 asset_id、序列位置 | 翻到下一页仍在组内；关闭定位到刚看的照片 |
| 普通图库 | 原有筛选、sort、max_id、位置 | 首页条件不污染；原有地图上下文不丢失 |

检查点：`setView`、`viewPanel`、`titles`、导航 active、面板 hidden、`updateChrome`、`refreshStatus` 的扫描结束分支、全局搜索/筛选、保存后刷新、`currentBrowseContext`、`browseContextKey`、waterfall 查询及签名、continuity snapshot/signature/support 判断。

新增 home/recommendation 不能仅放进 titles 就算支持。老 sessionStorage 无新字段要兼容；禁止存储时仍可浏览。异步请求须有 AbortController 或 generation 校验：快速切换类别或离开首页后，迟到响应不能覆盖当前页面。

第一版推荐详情不增加叠加人物/地点/文件夹筛选器，避免隐含第二层范围。用户需要自由筛选时，提供明确“到全部照片中查看”入口，并只传递可正确表达的条件；无法表达时不提供该快捷入口。

### 11.3 隔离、性能和真实入口

- 用独立 PHOTO_LIBRARY_DATA，启动后通过 health/status 核实实际目录、端口、PID；不是只看启动命令。不要打正式 data/。

- 原图及已有预览如需供隔离展示，明确只读边界，不把生成/清理操作指向正式缩略图目录。无法准备真实预览时记录限制，不能用生成图冒充验证。

- 冷查询超过 3 秒或暖查询 p95 超过 1 秒，先查 EXPLAIN QUERY PLAN、重复 COUNT、无界 JOIN 和缓存穿透。优化不行则如实标明未达目标，禁止用 loading 动画声称性能达标。

- 验证后记录最终涉及源码 SHA256 或等价可核对指纹。若又修改影响行为的代码，重跑对应案例；不能用旧版本证据给新版本签字。
