阅读方式：先看第 1 节的改动总览；实施时按第 3 节逐项修改；复核时使用各项验收表和第 4 节的检查方法。第 5 节提供进度表和交付清单。本文是待执行方案，其中界面表现仍需结合真实页面核对。

## 1. 本轮改什么

### 1.1 本轮要交付什么

1. 照片上的必要操作容易看见、容易点击，普通卡片、选中状态和整理状态可以区分。
2. 回忆可以暂停、继续，结束后可以从容选择下一步。
3. 已命名人物优先进入照片浏览，待确认人物继续便于身份核对。
4. 大图工具按用途组织，保留标签主题、原有快捷键、地图、收藏和导出能力。
5. 首页在现有三个回忆卡和三个推荐方向基础上精修；不重做推荐体系。
6. 交付同条件前后截图、核心交互记录、检查结果和未完成项，能由另一位执行者复核。

### 1.2 任务总览

| 任务 | 用户能感受到的变化 | 优先级 | 验证重点 |
|---|---|---|---|
| T1 配色和可读性 | 状态分得清，照片上的按钮看得见、点得准 | 先做 | 对比度、字号、点击范围、操作不误触 |
| T2 回忆播放 | 可以停下来细看，结束后自己决定下一步 | 先做 | 暂停、继续、最后一张停留、返回位置 |
| T3 人物详情 | 熟悉人物直接看照片，待确认人物方便整理 | 随后 | 两类人物的首屏主次和原有整理功能 |
| T4 大图工具 | 常用操作集中，主题选择能看见效果 | 随后 | 工具完整性、四主题、窄屏、标签导出 |
| T5 首页与页面一致性 | 卡片、文字、留白更统一 | 最后精修 | 同照片前后对照、桌面与窄屏、跨页浏览 |

### 1.3 设计方向

以下方案来自本次项目分析，具体布局需要在实际照片中调整。配色、字号、按钮点击范围等有明确目标；首页是否改变卡片大小属于审美选择，不预先要求改成另一种布局。

| 项目 | 本轮方案 | 范围说明 |
|---|---|---|
| 整体风格 | 保留灰白底、灰绿侧栏、深绿主操作 | 全站换肤、大面积金色、装饰插画 |
| 首页 | 保留三个回忆卡，先改善标题、留白和操作层级 | 强制改成一大两小、另加导航体系 |
| 人物 | 按已命名／待确认调整操作主次 | 重做人脸识别或人物分组 |
| 大图 | 整理工具位置和分组，保留现有能力 | 换查看器、重写照片坐标体系 |
| 播放 | 增加暂停和稳定结束页；保留默认每张 6 秒 | 音乐、视频导出、新播放速度设置 |
| 数据 | 复用已有照片、姓名、时间、地点和推荐结果 | 大模型、云服务、手工相册、新推荐算法 |
| 交付 | 完成源码和隔离验证，再如实记录正式页面验证范围 | 自动重启正式服务、提交推送或发布绿色包 |

优先级：照片和资料归属正确 ＞ 原有功能不退化 ＞ 操作清楚 ＞ 视觉细节。不得通过藏掉姓名、减掉功能、裁掉重要人物或修改照片内容来获得“更干净”的截图。

## 3. 任务清单与局部验收

### T1／优先：颜色分工、文字与点击区域

**现状与影响：**浅绿同时用于普通人物卡、选中状态和部分筛选区域，状态容易显得接近；照片上的部分文字过小、过淡。需要保持安静的界面，同时让操作真正可用。

**目标：**保持原配色，提高信息辨识和操作可达性。

**实施要求：**

- 保留基础颜色：背景 `#F7F8F6`、侧栏 `#EEF2EF`、主操作 `#285C49`、正文 `#25342F`、辅助文字 `#596A61`。确需微调要以实际对比度或视觉证据解释，不另造一套品牌色。
- 普通内容卡接近白色；选中状态用浅绿加明确边框／标记。已命名状态不能只靠与“选中”相似的底色表达。
- 首页低频动作可收进一个“更多”入口，保留“换一组／暂时不推荐／恢复隐藏”的现有能力。动作点击不得冒泡打开照片组。
- 本轮新增或修改的操作文字默认不小于 12 CSS px，主要操作宜为 13–14px；不通过给整个控件叠低 opacity 来弱化文字。
- 照片覆盖层使用稳定底色。按最终合成背景测量，不只比较 CSS 中的前景色和背景色。
- 进度圆点可以保持 6px 外观，按钮点击区域至少 24×24px且互不覆盖。首页“更多”和播放主要按钮点击区域至少 32×32px，触屏环境优先 40×40px。
- 文字、图标、边框、hover、focus、选中与禁用状态应一致，禁用仍需能够辨认；不引入在线字体或外部素材。

**验收 A01–A05：**

| ID | 复核方法 | 通过条件 |
|---|---|---|
| A01 | 读取本轮相关控件 computed style 和 DOM 边界 | 字号、点击尺寸符合上述要求，邻近热区不重叠 |
| A02 | 深色、浅色、杂色照片各抽一例，测量常态和焦点态 | 操作文字合成对比度至少 4.5:1，必要图标／焦点边界至少 3:1；作为本卡局部门槛，不宣称全站无障碍认证 |
| A03 | 鼠标、Tab＋Enter／Space、触屏点击“更多”及子动作 | 均可操作；不会误开组；关闭后焦点回入口 |
| A04 | 同屏比较已命名／未命名、选中／未选中人物卡 | 每类状态可用文字或形状识别，不只依靠色差 |
| A05 | 隔离库执行换组、隐藏和恢复 | 保留原数据范围与恢复路径；失败有可见反馈 |

### T2／优先：回忆暂停、继续与结束停留

**现状与影响：**当前回忆会自动推进和结束关闭。用户想辨认合影中的人、读照片细节或在结束后看完整组时，缺少稳定停留的机会。普通大图已有播放能力，本项应明确只调整首页回忆播放器，避免两个播放器的计时器和快捷键相互干扰。

**目标：**用户能停留在一张照片，播放结束后有充分时间决定下一步。

**状态与交互合同：**

| 状态 | 行为 |
|---|---|
| 首次打开 | 每个浏览器标签页会话首次保留现有片头，可点击或按空格／Enter／右箭头跳过；同会话后续打开直接进照片 |
| 播放中 | 默认每张 6 秒；显示“暂停”，空格暂停；左右箭头翻图；按钮获得焦点时 Space／Enter 只执行该按钮，避免双重触发 |
| 暂停中 | 图像停留，平移／缩放动画一同暂停；显示“继续”；等待不会换图。暂停时左右翻图后仍暂停 |
| 继续播放 | 从当前照片继续，给予完整 6 秒观看时间；只能有一个有效计时器 |
| 最后一张结束 | 停留最后一张，显示“再看一次／看全部／返回首页”，不自动关闭，不淡成空白 |
| 再看一次 | 回第一张并播放，省略片头；结束后重复执行仍正常 |
| 看这张 | 打开当前照片的大图，asset ID 必须一致；暂停播放计时器；关闭大图回到该回忆同一张并保持暂停 |
| 看全部 | 沿用该组现有完整列表和快照规则，不把精选几张当成全组，不静默放宽筛选 |
| 关闭／返回首页 | 清理计时器和未完成的播放意图，恢复原首页类别、位置及入口焦点 |

输入框、select、textarea、可编辑区域获得焦点时，不截获空格和方向键。回忆层打开时焦点留在可见播放器控件内；Escape 关闭当前最上层界面，不能同时关闭播放器和大图。减弱动态效果偏好下，不新增强制平移缩放，暂停功能仍有效。

**验收 B01–B08：**

| ID | 复核步骤 | 通过条件 |
|---|---|---|
| B01 | 第一张播放 2 秒后暂停，等待至少 12 秒 | asset ID、序号、图像动画进度保持；文字为“继续” |
| B02 | 继续后观察 3 秒，再等至 6 秒附近 | 前 3 秒不跳图；正常前台测试中约 6 秒后只推进一张，加载等待单独记录 |
| B03 | 连续切换暂停／继续 5 次；暂停时手动前后翻 | 无重复计时器、跳两张或暂停失效 |
| B04 | 暂停按钮聚焦后按 Space，再在普通播放区按 Space | 每次只触发一次；按钮和全局快捷键不叠加 |
| B05 | 播到结尾后等待至少 15 秒；分别操作三个结束按钮 | 最后一张与结束控件始终可见，三条路径正确 |
| B06 | 打开第 3 张的“看这张”，关闭大图 | 大图是同一 asset；回忆回到第 3 张且暂停 |
| B07 | 播放／预载时关闭，等待至少 12 秒，再重新打开 | 不自动重开、不残留翻图；焦点返回入口 |
| B08 | 连续打开两组；键盘遍历；模拟 reduced-motion | 仅首次片头；焦点不进入背后页面；减弱动态效果生效 |

使用 1 张、2 张和 5–10 张三种隔离样本。补测一张预览失败／延迟的样本：失败可见或按既有规则跳过，不能无限等待，也不能把失败资源算作成功显示。延迟／失败注入只在隔离验证中进行。

### T3／第二优先：人物详情按状态区分主次

**现状与影响：**人物详情首先呈现命名、合并等整理操作。对于已经确认姓名的人，查看照片应更直接；对于还未确认的人，整理功能仍应醒目。

**目标：**看熟悉人物的照片更直接，核对陌生人物仍顺手。

**实施要求：**

- 已命名人物：姓名和别名清楚，“查看照片”成为主要操作；改名、合并、标为路人放入“整理此人物”折叠区域。打开详情不抢占姓名输入框焦点。
- 待确认人物：确认身份、命名、选择合并目标保持明显，不为了统一外观全部折叠。
- 沿用真实人物状态字段，不按照片数量猜身份；已命名但仍需核对的分支不能被隐藏。
- 名称、别名、合并按钮和页内提示保持现有语义，`合并` 仍为 `type=button`；人脸仍分页加载，不一次渲染整组。
- 人物详情、照片列表和返回使用现有入口，不新增人物页面或替换人物查询规则。

**验收 C01–C04：**

| ID | 复核方法 | 通过条件 |
|---|---|---|
| C01 | 打开已命名人物 | 首屏可见姓名和“查看照片”；单次点击进入对应人物集合 |
| C02 | 打开未命名／待确认人物 | 命名和合并入口直接可见，状态说明不丢失 |
| C03 | 隔离库分别命名、合并、查看错误提示及最近操作 | 成功和失败反馈位于相关面板；可撤销合同不变；仅浏览不产生写请求 |
| C04 | 详情加载第二页，进入照片并返回；再核对窄屏 | 不一次渲染全组、不丢失人物 ID，无按钮遮挡或横向溢出 |

### T4／第二优先：大图工具分组和标签主题选择

**现状与影响：**缩放、姓名、别名、方向、资料、播放等同时出现在工具区域。每项都有用途，但用途之间缺少分组，窄窗口时也可能占据较多看图空间。实际是否拥挤须用 T0 截图确认。

**目标：**常用操作容易找到，样式设置集中，照片拥有足够空间。

**实施要求：**

- 常用浏览操作保留在一级：上一张／下一张、缩放／适应、播放／暂停。收藏保留现有照片内入口，不重复增设一套。
- 资料入口继续访问时间、地点和人物；人名、别名、方向与排版相关操作归入清楚的一组。低频项最多通过一个折叠层到达，不做多层菜单。
- 保留播放间隔和定位文件能力。“定位”在空间允许时写为“定位原文件”，避免与地图入口混淆。
- 标签主题在现有面板内提供四个可点击小样：默认、素笺、茶棕、暗朱；不能只用色块且无名称。选择后当前照片立即预览，状态可辨。
- 保留每个主题已有字体合同、字号／透明度设置及控件适用规则；不增加字体或新的主题。
- 390px 窄屏默认使用可换行底部工具或紧凑展开区；常态下不让固定竖工具栏持续侵占图像侧边。展开的面板须可明确关闭。

**现状与影响：**首页当前为三个回忆卡，已有独立的分类页和连续浏览。剩余空间主要在照片、标题、说明、操作之间的主次；本轮没有真实截图，不能预先认定某种卡片比例更好。

- 核对全部照片、文件夹、地点、人物、合影、收藏的顶栏、标题、按钮圆角与间距；公共样式修改不能损坏固定工具区。

| ID | 复核方法 | 通过条件 |
|---|---|---|
| E01 | 1440、1920、2560 CSS px 宽度截图及 DOM 测量 | 标题／分类／内容左对齐误差不超过 4px；同级媒体框高度差不超过 4px；非内容需要的横向溢出不超过 2px |

## 4. 验证环境、现有脚本与运行方式（T6）

### 4.1 分开三类证据

| 层次 | 验证什么 | 不能替代什么 |
|---|---|---|
| 静态／快速冒烟 | 公共函数、JS 语法、既有防呆与空闲接口 | 实际视觉和播放行为 |
| 隔离浏览器 | 计时器、键盘、焦点、写入操作、异常状态、导出 | 真实照片下的裁切和视觉质量 |
| 正式只读页面 | 真实图片、响应布局、读路径、真实导航观感 | 命名／合并／收藏等正式写入验收 |

隔离服务必须显式设置独立 `PHOTO_LIBRARY_DATA`，需要使用隔离静态副本时同时设置 `PHOTO_WEB_ROOT`。启动后先检查 health 的数据目录与端口，再操作。只停止本轮自己启动且确认归属的隔离进程。

注意：正式服务直接提供 `web/` 静态文件，编辑这些文件可能影响用户下次加载。优先使用隔离静态副本或独立工作区预览。若使用新 worktree，要先保留并核对当前未提交前端改动；不能从旧 HEAD 开始，导致本轮把已有功能覆盖回去。
