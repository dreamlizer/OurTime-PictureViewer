## 0. 执行摘要：采用什么方案

采用 **一个大图显示控制器 + 一个页面/照片流动效协调器**，各自负责不同层级，不建设全站状态框架。

大图控制器区分三件事：

1. **当前已提交画面**：一份有身份、有版本的照片显示快照。
2. **正在准备的下一张**：独立请求上下文，不能提前成为当前照片。
3. **打开/关闭的生命周期**：决定当前快照还有没有操作和重绘资格。

照片身份只通过 `commitDisplay()` 更换。同一张照片的缩放、主题、收藏状态等变化，也经控制器调度的受控刷新进入同一渲染边界，而不是重新下载照片或再触发入场动画。

页面切换分为 **不同面板切换** 和 **同一照片流容器换源**。后者包括公众人物与全部照片：它们共用 `#library-view`，不代表它们是同一数据源。每次切换只选一个负责内容透明度的层级；不能面板、网格、卡片同时入场。

实施分六个阶段：

| 阶段 | 本阶段只解决什么 | 独立通过条件 |
|---|---|---|
| P0 | 当前入口、补丁、可运行测试基线 | 知道实际调用者、可重现路径、最终浏览器加载的文件 |
| P1 | 显示会话、请求身份、关闭失效和统一入口外壳 | 旧会话无权驱动新画面；同 ID 重开也隔离 |
| P2 | 准备/提交拆开，收口标签、签名、按钮和同图刷新 | 新照片只由一个事务提交；load/zoom 不直接绘制业务内容 |
| P3 | 大图动效与冻结导出接线 | 一层负责照片动效；关闭可靠；导出不带中间透明度 |
| P4 | 页面/同容器换源动效归属 | 换集合无三层叠动画，无旧源卡片被当新源点击 |
| P5 | 竞态、回归、最终文件身份、日常版本应用 | 硬门槛有实测证据，不用旧测试或组件替身冒充全入口通过 |

**阶段纪律：** P1/P2 不同时重写页面动效；P3 不顺手改瀑布布局；P4 不顺手改人脸识别。阶段失败先停在本阶段修复，不带着未解释失败继续扩范围。

## 2. 产品不变量：不能为了整洁而改变的行为

### 2.1 可见身份与时序

- 初次打开 B，只可先展示 **B 的 seed** 或中性占位；不能出现 A 的姓名、签名、收藏、地点或资料。
- A→B 加载时，可保持 A 的完整已提交画面，角落延迟显示“加载中”。不能提前换成 B 的签名、按钮目标或计数，却还显示 A 的图。
- B 已就绪后，主图、标签、签名、收藏、地点和当前照片资料在同一个受控提交中切换到 B。
- 最新请求失败：有 A 则保留 A 并解除该请求的加载锁；无已提交照片则显示当前目标的失败说明和重试/退出入口。旧请求的失败不影响当前画面。
- 一旦开始关闭，当前会话立即丧失重绘与操作资格。可以保留旧 DOM 做关闭动画，不能保留可被回调重新激活的当前照片。
- 同一 photoId 的两次打开是两个会话；A→B→A 也是不同提交。只比较 photoId 不够。

### 2.2 保留精细业务合同

- 原照片只读，不移动、不删除、不修改 EXIF。
- 人名主题、字体、别名模式、英文例外、路人/待命名语义保持执行时最新已确认版本。
- 保留素笺 1/7、茶棕 4/8 的方向底板、暗朱规则、缩放系数、手动坐标和避让约束。
- 不恢复已经取消的重复悬停姓名提示；保留现有高亮/连接线及纠错入口。
- 拖动保存/回退、命名、拆分、路人、收藏、补录沿用现有后端请求与幂等/队列合同。
- 导出继续冻结当前稳定成品、使用原图、保留字体底板和签名；不改成低分辨率截图，不扩大资源白名单。
- 浏览序列、过滤、原图/预览选择、回到原浏览位置和人物详情滚动位置保持。
- 保留已确认的向前/向后轻柔切换及关闭渐隐；减少动态效果模式是明确例外，不是隐藏故障的办法。

### 2.3 唯一提交不等于“所有 DOM 更新都塞进一个巨函数”

允许三类清晰边界：

1. **显示内容提交**：控制器调用 `commitDisplay()`，内部调用既有标签、签名、收藏等低层绘制器；只有它能采用新的照片身份。
2. **壳层变化**：打开、seed、加载提示、失败提示、关闭动画与清空，不得携带未提交照片的业务信息。
3. **已提交画面内的瞬时交互**：拖动反馈、hover、高亮、输入光标等可以更新局部 DOM，但必须持有当前 FrameLease，不能更换照片身份或绕过写入入口。

缩放、主题等用统一调度请求同图刷新；刷新仍走内容提交边界，只画 dirty 部分，不重复取 detail，不重建整个面板，不重播换图动画。

## 3. 目标状态机与数据所有权

### 3.1 状态不是一个容易互相覆盖的单一 loading 布尔值

用户故事可简写为 `closed → seeding → loading → committed`。工程实现必须能同时表达“显示 A、加载 B”，建议在同一个控制器状态对象中使用以下正交字段：

| 状态域 | 内容 | 所有权 |
|---|---|---|
| lifecycle | `closed / open / closing` | 仅显示控制器写 |
| content | `empty / seed / committed` | 仅壳层入口或 commitDisplay 写 |
| committed | 当前已提交 Frame，或 null | 唯一当前照片权威；不可由业务回调随意就地改变 |
| pending | 请求上下文或 null：目标、token、准备进度 | 请求处理器产出结果，控制器决定采用 |
| motion | 当前动效种类、owner、transitionId、完成状态 | 动效适配器；不是第二个照片状态源 |
| interaction | 缩放/fit、拖动、控件禁用原因 | 控制器管理的局部状态；人物队列仍归既有业务运行时 |
| exitContext | 离开时的照片 key、序列位置、浏览范围与滚动信息 | 只用于导航恢复，不含可驱动画面的大份 detail |

`content=committed(A), pending=B` 合法。此时 A 仍是唯一已提交画面，不允许按 B 更新 A 的标签。B 加载失败时清除 pending，A 无须重新提交或重新取数。

### 3.2 状态迁移表

| 事件 | 前提 | 必须做的事 | 可见结果 |
|---|---|---|---|
| open(B) | closed | 新会话；清理旧活动数据；准备 B；可显示 B 的 seed | 无 A 的任何附属信息 |
| open(B) | closing | 使旧关闭任务失效；建立新会话；按 B 初次打开处理 | 旧 close/timer 不能关闭 B |
| next(B) | committed A | 建立 B 请求，保留 A；冻结原图相关写入口，导航/退出保持可用 | A 完整等待，必要时角落提示 |
| ready(B) | B 的请求和会话仍有效 | 用 candidate 进入 commitDisplay | 整套 B 在下一可见帧一致出现 |
| ready(A旧) | 请求或会话失效 | 只释放资源/完成 promise | 不改 DOM、loading、错误、焦点或按钮 |
| fail(B) | 当前请求 | 保留 A 或显示 B 初始失败；解除属于 B 的 pending | 不硬清空 A，不跳回更早请求 |
| refresh(reason) | 有有效 committed Frame | 合并 dirty 标志，执行前再次校验租约 | 同图更新，不换身份、不播入场 |
| beginClose | open | 先保存 exitContext，再使租约失效、取消读任务、关闭交互资格 | 当前静态 DOM 仅用于渐隐 |
| closeFinished | 当前关闭任务 | 最终清空、native close、恢复正确焦点/滚动 | closed，无活动 detail |
| commit抛错 | 有/无先前 Frame | 终止发布，恢复先前一致画面或中性错误态 | 不宣布提交成功，不留半套按钮与标签 |

### 3.3 身份票据：请求 token 与显示租约分开

**请求票据 RequestToken** 建议含 `sessionEpoch + requestSeq + targetKey`。每次打开重建 epoch，每次选择新目标递增 requestSeq。重复选择同一 ID 也产生新的请求序号或明确复用同一请求，不隐式混用。

**显示租约 FrameLease** 建议含 `sessionEpoch + commitSeq + photoKey`。用于 rAF、字体、ResizeObserver、收藏/位置 UI 回执、导出冻结资格等。A→B→A 即便 ID 相同，commitSeq 不同，旧租约仍无效。

主题/字体/别名变化另外使用控制器持有的 **visualRevision**；布局完成对应的 renderedRevision 必须可追溯。不要让每个模块自行创建一套“当前 version”。

这些是语义要求，不要求无条件增加全部新计数器：优先将现有 `generation / presentation / faceRenderGeneration` 映射成上述职责；过渡期保持薄适配，不同时保留两套可以各自变动的权威版本。

`AbortController` 用于停止无用工作，不是身份检验的替代。取消失败、已经排入微任务/rAF 的结果仍须拒绝。

### 3.4 显示快照与候选数据

**PreparedDisplay（未提交）** 至少携带：请求票据、稳定 photoKey、独立 detail、选中文件、已核对的图片源、就绪图片句柄、必要资源结果、准备时视觉版本。准备期间不得修改 `state.detail`、当前 DOM、当前照片 entity session 或收藏按钮。

**CommittedFrame（已提交）** 至少携带：photoKey/photoId、来源范围标识、commitSeq、detail 快照、文件/图片源、实际有效主题及视觉版本、真实几何、可用操作能力。业务组件只读；字段更新通过显式事件生成下一版，而不是直接持有并到处修改共享对象。

不要求对大份 metadata 每帧深拷贝。照片采用时建立边界，更新时结构共享；开发态可冻结关键顶层字段。已经发送的写操作保存独立 payload，不因显示快照失效丢失归属。

`photoKey` 对私人照片可为稳定 asset ID；若当前公众人物入口使用参考图/相对路径而非私人 asset，采用其既有资源 key，不编造私人 ID。只有具有私人照片能力的 Frame 才允许收藏、命名、坐标保存和现有导出。

### 3.5 state.detail 与 DOM dataset 的定位

- 迁移期 `state.detail` 只能是控制器发布的兼容只读视图；不再是第二个可自由赋值的数据源。
- `dataset.photoId`、测试用 commitId/sourceKey 等是观察镜像，不以读 DOM 的结果倒推权威状态。
- 清空 `state.detail` 必须在捕获 exitContext 之后；不能破坏瀑布返回位置。
- 既有草稿可以继续按照片存放在 `viewer.drafts`，但它不是“当前照片”。关闭后的草稿和后台队列没有主动刷新 DOM 的权限。
- entitySession 的当前显示资格可以失效；已入队操作仍按原实体处理。不得因关闭大图而回滚已成功保存的数据。

### 3.6 序列位置与焦点也有显示归属

导航意图可以先更新 requestedIndex，但顶部“第几张/共几张”、退出返回的位置应来自已提交帧对应的 displayedIndex，而不是尚未就绪的目标位置。加载失败不把序列游标永久留在失败目标；继续浏览仍从当前可见照片按原序列合同处理。

保留现有连续导航的合并策略，不要求把用户快速点击的每一张都完整显示。要求的是最后一个有效目标正确、显示序号与画面一致、过期请求不反向跳回。推荐快照、地图固定范围及公众人物组信息不能在生成 sourceKey 或简化 context 时丢失。

关闭返回焦点/滚动也必须核验原入口是否仍存在、所在页面是否仍有效。native close 事件、关闭 timer 和动画结束只能各自通知同一个幂等关闭入口，不得重复恢复焦点或让旧关闭事件清空新会话。

## 4. 模块边界与接口合同

### 4.1 最小模块划分

| 模块 | 负责 | 不负责 |
|---|---|---|
| `viewer-display.js`（建议新增） | 状态、票据、准备协调、唯一提交、刷新调度、关闭失效 | 不复制主题表、不做人脸匹配、不接管全站路由 |
| `viewer.js`（保留） | 工具栏、用户动作、现有几何/标签/签名绘制；向控制器发请求 | 不再独立发布当前照片，不在 load/zoom 随意取全局 detail 重绘 |
| `app.js`（小范围适配） | 公共函数、API、既有 entity/operation runtime、资料纯准备和绘制适配 | 不通过 renderPhoto 包装暗中第二次取数、开窗或提前发布 detail |
| `view-transition.js`（建议新增，可先作为 app 内明确区段） | 页面切换计划、sourceKey、opacity owner、完成/取消 | 不重写搜索筛选、瀑布列布局、地图业务 |
| `waterfall.js`（保留） | 页缓存、虚拟化、布局、挂载、首批换源提交 | 不再独立决定与面板冲突的整批入场 |
| `face-label-model.js / face-labels.css` | 既有标签展示规则 | 不决定当前照片生命周期 |
| `photo-export.js` | 绑定帧的导出操作、稳定快照 | 不从等待后的任意全局 state 换照片，不控制显示状态 |

默认不新增超过两个核心 JS 文件；纯函数测试文件另计。先建立边界、转接调用，再决定是否抽物理文件；不以拆出多少文件衡量完成。

### 4.2 加载与初始化

当前脚本顺序包括 operation-runtime → app → home/map → face-label-model → viewer → photo-export → recent-operations → browse-continuity → waterfall → home-query 系列。[S7]

新增显示模块应只声明 factory/API，不在载入时读取尚不存在的 `viewer`。建议在 face-label-model 之后、viewer 之前加载，由 viewer 构建 DOM 及适配器后显式初始化一次。页面动效模块若置于 app 之前，载入时同样不得读取尚未定义的 state。

`app.js` 的 esc、prettyPlace、personLabel 等保持原位置。禁止用全局占位空对象吞掉依赖遗漏，再声称启动成功。新增脚本路径和初始化次数要纳入完整入口测试。

### 4.3 关键接口（仅签名级示意，不是实现代码）

```text
openDisplay(target, browseContext) -> Promise<DisplayResult>
prepareDisplay(target, requestToken) -> Promise<PreparedDisplay>
commitDisplay(candidateOrRefresh, ticket, options) -> CommitResult
requestDisplayRefresh(reason, frameLease, dirtyFlags) -> void
getCommittedFrame() -> Readonly<CommittedFrame> | null
beginClose(reason) -> Promise<CloseResult>
captureStableExport(frameLease) -> Promise<FrozenExport>
planViewTransition(from, to, context) -> TransitionPlan
```

接口边界：

- `prepareDisplay` 可以 await；`commitDisplay` 的发布区间不得 await 或再次请求照片。
- `requestDisplayRefresh` 只排队，执行时重验租约；失效后不“改用当前 detail 继续”。
- 外部代码拿不到可自由修改 committed 的引用；getCommittedFrame() 在 closed/closing 或尚无正式提交时返回 null。加载 B 时可以只读取得仍在显示的 A，但可执行动作另按 loading 等禁用原因判断。
- `DisplayResult/CommitResult` 区分 committed、stale、failed、cancelled；stale 不是成功，也通常不是用户错误。
- `captureStableExport` 绑定调用时的帧；稳定前切图/关闭则取消本次冻结，不能悄悄导出后来那张。

### 4.4 同步提交事务的步骤

1. 最后核对请求 token、目标 key、生命周期、图片源与 detail 身份，以及视觉资源版本。
2. 先准备会抛错的展示数据/必要离屏节点。不能一边取网络数据一边改活动界面。
3. 暂停提交区间的重入；计算下一版 Frame。此时仍不向外暴露“B 已提交”。
4. 将准备好的图像放入主图槽位，更新资料、签名，再根据真实图像区域计算 fit 和标签位置；绘制收藏/地点等同照片控件。
5. 同步设置最终身份镜像、发布 committed Frame、使同图动作读取新的租约。内部绘制器接收显式 Frame，不依赖临时写一半的全局 state。
6. 在下一次绘制前确认所有相关节点身份一致。首次提交需要额外帧测量时，使用准备态隔离或旧画面维持，不能公开半套新内容。
7. 启动本次唯一入场动效；同图 refresh 不执行本步骤。结束前拒绝导出中间动效态。
8. 解除本请求的加载锁，按统一能力/锁定原因计算按钮状态；不会因别的同步函数一句 disabled=false 而提前解锁。

这不是 DOM 数据库事务，不能假设“函数同步就自动安全”。需先准备、后发布，并对绘制异常有明确回退。禁止 catch 后只记录日志却把 phase 写成 committed。

### 4.5 主图节点、seed 与图片解码

- 保留外部 `#detail-img` 槽位合同、所有相关布局 ID 和导出定位方式；不克隆整套 viewer。
- **推荐：** 候选图在离屏 Image 上加载/解码完成，提交时进入唯一主图槽位。只替换图像节点，不重建工具栏/标签层/签名容器。
- 如采用替换 Image 节点，P2 必须一次性迁移原来直接绑在旧 `#detail-img` 上的 load、dblclick 等事件，采用稳定容器委托或由控制器显式绑定/解绑。不得留下指向旧 image 的缓存引用。
- 若保留同一个 img 对象，也必须证明最终画面读取的是本次准备的就绪源，且 src 切换过程中无可见错配/空图；不能仅以另一个 Image 的 load 成功推定活动节点已经稳定。
- `decode()`/load 失败执行明确预览回退或失败分支；禁止吞掉解码错误后无条件宣布就绪。[W1]
- seed 可单独由壳层显示，但必须绑定本次请求，只能作为视觉占位；它的 load 不可触发业务标签、签名和操作能力。
- 新打开 B 的 seed 难以从卡片得到时，宁可中性占位，不拿 A 的主图伪装 B。

## 5. 所有异步入口的迁移清单

| 现有入口 | 新职责 | 进入前/回调时的检查 |
|---|---|---|
| `openPhoto / displayPhoto` | 请求控制器，准备候选 | session + requestSeq + targetKey |
| `renderPhoto / applyPhotoDetail` 及包装层 | 纯准备或提交内资料渲染适配 | 不在控制器之外改当前照片 |
| 主图 `load` | 通知指定图片就绪，或申请当前帧几何刷新 | 对应源/图片实例；不得用旧 load 采用新全局 detail |
| `updateZoom` / ResizeObserver | 更新 viewport 意图，申请 geometry dirty | 执行时仍是相同 FrameLease；不反向触发 load 链 |
| 主题、字体、别名、方向 | 更新偏好与 visualRevision，申请 style/labels dirty | 租约 + 视觉版本；失效只保留用户偏好，不刷新旧图 |
| 字体完成、底板探测 | 缓存资源结果；申请当前仍相关的刷新 | 请求主题/字体版本匹配，关闭时不碰画面 |
| 收藏回执 | 更新其实体缓存/计数；符合租约才刷新本帧 | photoKey + 操作版本 + 显示租约 |
| 坐标写回/命名/拆分/路人 | 复用现有队列；结果转为实体 patch | 原实体归属；本帧引用相应实体且仍有效才绘制 |
| 签名补录日期保存回执 | 更新原照片资料，不强制重新 open 原图 | 切到 B 后不得被 A 的回执拉回去 |
| 导出字体/稳定等待 | 等待绑定帧稳定，冻结前复验 | commitSeq / photoKey / visualRevision |
| 加载指示、关闭 timer | 壳层或动效收尾 | 任务身份匹配，不能旧 timer 隐藏新状态 |
| `revealPanel` 的 rAF | 只结束当前 view transition | 在 rAF 内重验，不只在排队前检查 |
| 瀑布首批/分页/连续性恢复 | 返回数据与就绪结果，提交指定 sourceKey | view token + waterfall generation + sourceKey |

### 5.1 同图刷新避免死循环

统一合并同一帧中的 dirty 原因：geometry、labels、signature、actions、detail-panel。一次刷新中几何可影响标签，但标签不能再次触发全图刷新；保留签名 fit 的有界迭代，不改成 ResizeObserver 反复自激。

纯颜色变化不重载图片。字号/字体变化可重新测量标签；不得清坐标或重复写坐标。拖动期间一般延迟标签整体重排，拖动结束再处理最后版本；切图/关闭时取消未完成手势，不保存半次拖动。

## 6. 写操作、收藏、草稿与导出：显示失效不等于数据取消

### 6.1 两类生命周期必须分开

**读取/渲染任务：** 旧会话失效就无权采用，能 abort 则 abort。

**用户已经提交的写操作：** 继续绑定原实体完成或按现有机制确认结果。不能因为用户关闭窗口就当成“没有保存”，更不能用 abort 当作服务端回滚证明。

切到 B 后 A 的写入成功，可以更新 A 的缓存和全局计数；不能把 B 的收藏图标点亮、改 B 的脸、弹 A 的照片内错误或重新打开 A。再次回 A 时读取已提交事实，而不是复活旧显示租约。

### 6.2 收藏的具体要求

- 点击时从有效 committed Frame 捕获照片 ID 和目标 favorite 值，不从 pending 读取 ID。
- 保留原接口。改造仅限显示归属、回执版本、按钮锁定和必要缓存刷新。
- 按照片跟踪 pending；同一 DOM 按钮被 B 复用时，A 的 finally 不能给 B 解锁。
- 禁用原因至少区分：未提交/关闭、照片切换、当前实体写入、导出锁、主题资源限制、能力不支持。它们通过一个计算入口合成，而不是多个函数抢写 disabled。
- 从收藏列表打开后取消收藏，仍使用既有 favoriteViewDirty/列表刷新语义；退出后不恢复到错误集合。

### 6.3 位置/人物与草稿

- 已发送坐标队列和 operation ID 不重写；拖动反馈属于当前帧，写入 payload 独立保存 faceId、photoId、归一化坐标。
- pointercancel / 关闭 / 换图使手势失效并释放捕获；随后的 pointerup 不能提交旧按钮。
- 重排只根据现有坐标显示，不能自动“修正”并回写坐标。
- 姓名修改属于人物实体，可能影响多张照片；显式将结果送进当前帧投影，不靠旧 detail 共享引用碰巧刷新。
- 草稿仍按照片保存；加载下一张资料不能覆盖同张用户正在编辑的输入。关闭清活动态但不擅自删除现有约定允许保留的草稿。
- 单张纠错与整个人物更名的作用域不变，不借本轮修改确认流程。

### 6.4 导出冻结的明确时点

1. 点击导出时捕获 FrameLease 与视觉版本，建立独立 exportOperationId。
2. 有 pending 换图、关闭中、seed、几何未稳定或动效未结束时，禁止开始新冻结，说明准确。
3. 已开始等待字体/稳定状态时若发生换图或关闭，取消这次尚未冻结的操作；不改为导出新照片。
4. 冻结成功后，即使稍后换图，导出请求继续使用已冻结 A；操作提示不能污染 B 的照片内状态。
5. 冻结的是稳定成片属性；不能带入 opacity=.3、临时 translate、旧入场 class、悬停弱化、focus、控制按钮等。
6. 新动效若落在 `#photo-mat` 或祖先层，必须检查冻结采样及后端样式收集。不能只删除 class，却把过渡中 computed style 保留成内联样式。[S8]
7. 保留签名、底板、实际字体、原图尺寸与既有背景边框；不删除所有 transform/filter，因为其中可能有合法成片效果。
8. 白名单、请求限制、输出格式/命名不变；原图 hash 仅用隔离样本验证。

## 7. 动效合同与唯一归属

### 7.1 先决定 owner，再加载数据；不再让各层自行发挥

| 场景 | 唯一负责“内容入场/退场透明度”的层 | 其他层规则 |
|---|---|---|
| 首次打开大图 | 大图受控内容层或现有对话框内容层，二者只选其一 | 首张不能再叠主图、标签各自入场；backdrop 可独立变化 |
| A→B 换照片 | 同一坐标体系中的成片内容层，建议 `#photo-mat` | 主图与标签一起变；父 dialog 不重复淡入；签名不得闪旧内容 |
| 关闭大图 | 现有关闭动效层 | 先取消照片入场，再关闭渐隐；只有当前 close ticket 能最终 close |
| 首页→人物/地点等不同面板 | 页面协调器控制面板过渡 | 新面板中的首屏网格/卡片不再叠整批入场 |
| 公众人物↔全部照片 | 照片流换源 owner（grid 级） | `#library-view` 不整页淡出；首批卡片抑制入场 |
| 当前集合正常向下滚动追加 | 新进入视口的卡片 | panel/grid 稳定，不启动换源动画 |
| 标签主题/缩放/收藏状态变化 | 无照片级入场动画 | 允许既有局部控件反馈，不重新淡入整张照片 |

“一层”指同一内容及其祖先不能同时承担此次切换淡入。标签的静态透明度、按钮 hover、独立背景遮罩不等于违规；不能为了通过计数把所有交互动画禁掉。

### 7.2 动效状态、类名与取消

- 每次动效有 transitionId，记录 kind、owner、关联 FrameLease/view token。
- 同一 owner 新任务开始前取消旧任务、清理残留 class、收敛到明确状态；旧 end/cancel/timer 不可结束新任务。
- 保留 `viewer-photo-arriving / viewer-photo-forward / viewer-photo-backward / viewer-closing` 的产品语义。可改变挂载层或封装，但 JS、CSS、smoke 同批迁移。
- 基线的页面约 140ms、关闭 JS 150ms、加载提示延迟 220ms 用于 P0 对照；实际以读取到的完整 CSS 和运行效果记录为准，不统一改为某个“感觉更高级”的长时长。
- 页面 is-switching / is-pending / is-ready 不应造成等待时先亮一次、又变暗、再亮。pending 主要负责提示，不应成为第三次透明度阶段。
- 动效正常完成用事件/动画完成对象；同时处理取消、0 时长、reduced-motion、元素移除和后台标签页，提供有身份校验的有界收尾。不能只依赖 transitionend。[W2]
- 关闭的逻辑失效不能依赖 rAF 或 CSS 事件；后台标签页的 rAF 可能暂停。[W3]
- 不引入全站 View Transitions API、截图跨页转场、双 viewer 树或大图交叉叠放，避免新兼容和导出问题。

### 7.3 同容器换源需要有“集合提交”，不只是改透明度

建立明确的 `visibleSourceKey` 与 `pendingSourceKey`。sourceKey 包含实际影响集合的条件：view/filter、人物、publicGroup、搜索词、目录、时间区间、地点、排序、推荐快照及地图固定范围等；分页偏移不是新的集合身份。[S5]

处理顺序：

1. 用户请求切到新集合，捕获不可变 query 和 view token；保留旧已显示集合。
2. 给旧内容准确的“正在切换”语义。旧卡片暂时不能用新集合 context 打开；推荐等待期间禁用旧网格的打开动作，侧栏/取消仍可用。
3. 仅网格 owner 播一次既定过渡；保留高度，避免先空白后重建。
4. 新首批数据和可显示卡片就绪后提交 visibleSourceKey、标题/计数/内容；同步切换点击 context。
5. 首批卡片预标记 seenPhotos 或使用明确的 batch entrance policy，禁止 panel+grid+card 叠动效。进入正常滚动后仍可执行未见卡片的既有入场。
6. 失败保留旧集合与正确标题/计数/点击归属，显示重试；不能“新页面标题+旧数据+新 context”。若保留用户待应用筛选，明确区分 pending 与 visible。
7. 提交后包括 requestAnimationFrame 的收尾都复核 view token + sourceKey；旧首批/分页/continuity 回调不得替换新页。
8. 不重写 waterfall 列数、缓存容量、布局算法、定位恢复；只协调首批换源与动效。

不同面板切换也要保留实际旧面板到退场结束，再隐藏它；不能提前 hidden 后假装播了淡出。新面板的内容准备与展示令牌绑定，加载慢时仍可导航离开，不能把整个页面锁死。

## 8. 分阶段实施步骤与出口

### P0｜先建立真实基线，不改业务与视觉

**步骤：**

1. 记录 HEAD、相关未提交修改、当前日常程序读取的静态目录；本任务不覆盖用户已有修改。
2. 读取最新 AGENTS、README、上述源文件与所有相关包装/赋值点；搜索不只限函数定义，还包括重定义、内联事件、导出和全局 API。
3. 建立“入口 → 异步边界 → 可写 DOM/state → 当前防护”的表，至少覆盖第 5 节。
4. 核对 `renderPhotoImplementation/renderPhoto` 包装：prepared 是否透传、取数次数、entity session 建立时点、识别状态提示是否保留。
5. 选择可重复的隔离 fixture：A/B/C 身份、姓名、签名与收藏状态明显不同；包含 A 再打开 A、无脸图、长中文名、中英文合影、横竖幅。
6. 建立浏览器完整入口检查：真实 index + 实际脚本顺序 + 实际 viewer，API 用隔离服务或仅网络层 fixture。禁止把 renderFaceNames/commit/applyStyle 本身 stub 掉后宣称入口正常。
7. 从当前版本记录四类故障路径的视频/逐帧证据或稳定结果；补丁已经修好的则作为回归基线，不故意改坏正式代码。
8. 跑现有 smoke，盘点旧测试是否指向日常 8765/正式库；不得未检查就批量执行。

**出口：** 基线、调用清单、fixture、完整入口命令明确，零静默替换源码。缺浏览器可完成静态规划，但不能继续宣称已通过运行门槛。

### P1｜建立生命周期与单一入口外壳

**允许区域：** viewer 入口/清理/调度，新显示模块及 index 接线；标签视觉与页面动效暂不改。

1. 明确状态域与旧字段的单向映射，创建唯一控制器实例。
2. 把 open/close/cancel/Esc/背景点击/人物详情返回统一到生命周期入口。
3. beginClose 立即使读任务和显示租约失效；先存 exitContext，再清活动 detail。DOM 渐隐不等于数据仍有效。
4. 实施同图重开与旧关闭 timer 防护；取消 loading/label edit/计划帧/手势，区分未提交手势与已发写入。
5. 给现有 compositor 包一层 commitDisplay 门禁，先复用其内部绘制；所有身份采用入口必须经过它。
6. 将 seed 限为无业务的壳层占位；load 只交付身份明确的通知。
7. 添加 epoch/request/commit 的状态测试；不要求此阶段完成全部物理文件抽取。

**出口：** A 关闭后开 B、同 ID 重开、closing 时再开、慢 seed 和迟到 load 全部不串；最终页面可以真正打开照片与样式面板；没有新未定义变量。旧补丁此时仍保留为兼容防线。

### P2｜收口 prepare/commit 与同图刷新

**允许区域：** app 的照片详情桥接、viewer 绘制链、必要业务回执接线；不改 API/数据库语义。

1. 去掉 prepare→包装 renderPhoto→再次 prepare 的隐式链。读取只返回候选，资料绘制和开窗分离；透传/保留所有当前需要的信息和副作用。
2. 各类正常打开/上一张下一张/推荐看这张/人物详情/地图返回只提交导航意图，不复制新显示流程。
3. 实现第 4.4 节提交事务。单一 src adopt 点、单一 detail 发布点、单一 shownId 镜像发布点可定位。
4. 将 load、updateZoom、ResizeObserver、applySrc、主题/字体完成改为统一通知/刷新请求，删除它们独立采用身份和直接画标签的资格。
5. 对主图节点替换方案明确事件绑定；预热、缓存图、失败回退使用相同 ready 合同。
6. 接入 signed dirty refresh：主题/几何/收藏/元数据，不重播入场，不重置焦点，不覆盖未保存草稿。
7. 对收藏、位置、人物、日期回执建立 FrameLease 门禁；原队列、operationId、服务端成功事实保持。
8. 分批删除被替代补丁，旧函数保留时仅转发，不保留第二个可绕过门禁的实现。

**出口：** 正常读取不因包装层无故重复；A/B/C 乱序和 A→B→A 不串图；一次换图只采用一个 candidate；主题与缩放更新不写坐标；旧写回执不改新画面。

### P3｜大图动效与导出冻结

**允许区域：** 大图动效 class/CSS、关闭完成方式、photo-export 接口桥接。

1. 先记录现有动效触发者、owner、keyframes 和时长；确认由单一 owner 负责一次照片切换。
2. 主图与标签采用一致坐标/动效层；避免图片自身移动而标签留在原位。
3. 普通对话框动画与 detail 专属动画分开；不改其他对话框样式。
4. 换图动画仅来自成功 replace 提交；主题/resize/收藏 refresh 不播放。
5. 动效取消/结束/reduced-motion/旧关闭回调都按 ticket 收尾，旧动画不覆盖新状态。
6. 导出绑定 FrameLease，等待稳定/资源后再次验证；清除瞬时显示效果但不改变合法成片视觉。
7. JS/CSS/smoke 成对迁移；过渡期旧类名可薄适配，最终不能两个 owner 都在运行动效。

**出口：** 前后方向正确，关闭渐隐且不误关新图；无硬切与重复入场；导出不捕获中途透明/位移，冻结后换图仍导出原照片。

### P4｜页面与照片流换源收口

**允许区域：** app 的 setView/prepare/reveal 段、waterfall 首批换源、appearance 动效相关选择器。

1. 依据 fromPanel/toPanel/sourceKey 选择 motion plan，不只堆 view 名字判断。
2. 同容器换源保留 preserveUntilReady 和 seenPhotos 的有效行为，写明首批与后续滚动不同策略。
3. 各分页/首批/rAF/continuity 后续结果带票据，不允许旧页面请求更新当前标题、计数或 grid。
4. 首批 swap 与集合标题/计数/点击 context 同步；旧网格待换源期间不可被按新集合解释。
5. 面板、grid、首批卡片入口互斥；加载提示与 opacity 阶段解耦，避免闪→暗→亮。
6. 失败和空集合分开：数据成功为空才展示空态；失败显示准确错误，保留可用旧内容或可恢复的新面板。
7. 保留筛选保存、浏览器前进后退、人物/地点跳转和返回定位。只做桥接，不重新设计这些流程。

**出口：** 首页/人物/地点/全部照片交叉切换正常；公众人物↔全部照片无整页额外淡出和逐卡齐闪；快速再切到第三页后旧回调无权恢复上一页。

### P5｜收口、最终验证与本机应用

1. 跑完整验收矩阵中的适用硬项，失败逐项修复；已失败用例不能改成 skip 逃避。
2. 复查入口/全局赋值清单：唯一采用点、唯一数据权威、明确动效 owner；移除已被替代的双轨写入与死监听。
3. 对最终文件实际执行浏览器加载，保存源码 SHA/文件 hash 与浏览器实际响应 hash；测试后又改代码必须重跑受影响门槛和基本启动。
4. 输出简短阶段结果与最终报告，明确真实运行、组件测试、网络替身、未验证内容；不要只写“全面优化”。
5. 本机安全条件允许时应用到用户日常使用的那份程序并检查刷新后的实际文件；不把成果只留在另一个副本。只改前端通常不需要重启后端，须以实际静态目录为准。
6. 正在扫描、存在未保存用户编辑、需要覆盖不明改动或涉及其他实际风险时，停在该风险边界并说清具体原因。不要创造额外“部署审批”流程。
7. 不自动运行全量扫描、识别、validate.py、绿色包重建，不推送远程。

**出口：** 本机日常版本与已测文件对应；功能与动效有证据；剩余事项只有明确非阻断项或真实阻塞，不伪称全部完成。

## 9. 自动化防呆：轻量日常检查与关键阶段真运行分开

### 9.1 不改变现有日常门槛

`python validation/smoke.py` 仍是日常检查入口，不把它变成全量 Playwright、扫描、人脸识别或分钟级业务回归。现有只读接口检查遇到扫描占用时按现行约定报告 SKIP，但不能把这样的 smoke 结果当作新分支浏览器验收。

本次专门改变时序，所以 P1—P5 的阶段出口另外运行 **聚焦显示测试**，不用 `validate.py` 替代。只有改变入库/人物业务合同等现有触发条件才使用全量套件；本任务原则上不触发它。

### 9.2 建议补充到 smoke 的静态合同

| 检查 | 应拦住什么 | 不能只怎样检查 |
|---|---|---|
| 脚本顺序和初始化 | 新模块晚于消费者、控制器初始化多次、核心文件漏挂载 | 只在仓库看见文件名 |
| 显示采用点 | load/zoom/回执又直接写当前 detail 或主图身份 | 只看是否存在 commitDisplay 函数名 |
| 准备纯度 | prepare 又开始 showDialog/写 DOM/重开 session | 函数注释写“纯”就通过 |
| 动效配对 | JS 还加类，CSS/keyframes 被删除；关闭没有样式 | 只找任意 opacity:0 字符串 |
| owner 约束 | 同容器换源又调用整页 prepare，首批卡片又批量入场 | 仅看 seenPhotos 字样存在 |
| 关闭失效 | 清 DOM 但未失效票据/计划任务；close 之后 detail 仍活动 | 只找到 state.detail=null 即判全部正确 |
| 导出接线 | 未绑定 committed Frame、漏读新样式或遗漏动效清理 | 单看返回 HTTP 200 |
| 关键交互 | 手动坐标、主题字体、原有 DOM ID 被抽取时误删 | 为了通过直接删除旧断言 |

可用清晰白名单、代码区段检查或复用现成语法解析工具定位合法调用点；不在这一轮自制通用 JS/CSS 编译器。函数迁移后把旧断言映射到等价/更强合同，不永久锁死不再合理的函数位置和字面拼写。

**负向检验：** 在临时内存副本或隔离文件中移除一项动画规则、颠倒依赖或增加一个非法直接写入，确认防呆会失败；不要修改日常文件来做故障注入。

### 9.3 三层聚焦运行测试

| 层级 | 建议内容 | 运行时点 |
|---|---|---|
| 纯控制器/状态测试 | epoch、request、commit、关闭、同 ID 重开、取消、数据锁 | 每次改状态或提交分支 |
| 完整前端入口测试 | 实际 index 和真实脚本；只替换网络响应，操作照片/面板/切页 | 每阶段最后一次修改后必跑 |
| 隔离后端联调 | 临时 PHOTO_LIBRARY_DATA；真实收藏、坐标保存和导出 | P2/P3/P5 相应关键出口，不每改一行就跑 |

建议文件名可为 `validation/test_viewer_display_state.*`、`validation/test_viewer_display_browser.py`、`validation/test_view_transition_browser.py`；名称是建议，不是宣称仓库已经有这些命令。执行者需提供真实存在、可重跑的入口。

### 9.4 完整前端入口测试的最低要求

- 加载最终 `index.html` 及所有真实脚本。不得只截取几段函数、把实际布局器替换成记录次数的 spy，就声称整体验收。
- 测试替身只在 API、图片、字体的网络边界；主控制器、实际标签布局、实际 CSS 和事件绑定仍运行。
- 收集 `pageerror`、未处理 promise rejection、关键失败网络请求；预期注入故障单独标记，不能全局吞日志。
- 检查的不只是截图有图：打开大图、切换主题、退出再开、左右导航的实际动作都要执行。
- 一次正常加载中的图片/详情请求次数应与设计相符；同一请求因 renderPhoto 包装额外取详情视为异常，原图失败转 preview 等显式回退除外。
- 同 photoId 的旧请求、相同 URL 的 seed 与高清、同步命中的缓存图，都必须覆盖。
- 功能测试可以另设 reduced-motion 以提高稳定性，但必须另有 **正常动效开启** 的测试证明没有硬切/闪烁。

### 9.5 可观测信息要足以定位，不增加常驻面板

开发态可留有界内存事件环，记录时间、event、session/request/commit、sourceKey 的脱敏标识、dirty reason、采用/丢弃原因、motion owner。只在调试开关下启用，不常驻发网络、写正式日志或打印姓名/私人路径。

关键计数：成功 replace 次数、过期结果丢弃数、非法显示写入数、每次稳定渲染/布局次数、动效 owner。**丢弃旧请求可以是正确行为，不应要求 staleDiscard=0；真正要求是 staleCommit=0。**

### 10.5 不靠最后一张漂亮截图判断时序正确

- 用固定 fixture 中不同的主图标识、姓名、日期和收藏状态核对实际内容，不只相信程序自己写入的 data-photo-id。
- 在关键提交边界与 requestAnimationFrame 记录可见快照；结合视频或测试截图查看发生切换时的中间帧。不要只等待 1 秒后截最终状态。
- 对首次打开、退出再进、左右连续切换、同容器换源各保留一段真实流程证据。
- 同步提交函数内部允许有不可见的多步 DOM 写入；验收重点是公开状态和浏览器可绘制帧不混身份，不能要求每个 MutationObserver 子记录都代表一张完整画面。
- 真实照片只留本地；自动化先用合成/获准样本。标签角花/实际字体和真实照片审美需另用本地样图观察，不能把无字体/假底板替身写成视觉通过。

## 11. 风险、边界与应对

| 风险 | 必须采取的措施 |
|---|---|
| 控制器变成第二套状态，旧 state.detail 仍自由写 | 全部写入点清单和白名单；迁移期单向镜像，阶段后删旧采用点 |
| 把准备图过早当当前图 | candidate 不发布；请求未完成时 current 永远是旧 committed 或 null |
| 单 ID 检查挡不住同图重开 | 使用 session+commit 租约，而非只比较 photoId |
| 包装 renderPhoto 或其他补丁隐藏额外副作用 | 搜索所有赋值/重定义，prepared 透传、取数次数与 session 时点实测 |
| 切换时 old detail 清掉导致返回定位/草稿丢失 | 清前采集最小 exitContext，草稿按照片保存，导航恢复不依赖活动 detail |
| 显示失效被误认为写操作取消 | 操作 payload 与队列独立；只取消旧 UI 采用，不篡改已保存事实 |
| 反复刷新让收藏按钮提前可用 | 多原因锁定统一计算；旧请求 finally 没有独立解锁权 |
| 替换主图节点漏绑原来的事件 | 稳定容器委托/显式 bind-unbind；全入口双击、load、放大和导出实测 |
| CSS transform 影响 getBoundingClientRect 与拖动坐标 | 图和标签使用共同坐标，动效期明确限制相关操作；稳定态测量、导出 |
| 冻结了动效中 computed style | 冻结前稳定校验，精确排除临时动效，不全删合法样式 |
| 页面有 view token，但 rAF 收尾未校验 | 回调执行时复验；所有旧错误/空态/计数也同样受保护 |
| 同容器旧卡片被新 state.view 解释 | visibleSourceKey 与点击上下文绑定，等待换源的旧网格禁用打开 |
| 测试看似全绿，实际只执行 pure model | 独立标注层级，最后一次修改之后强制全入口运行 |
| 为了测试省事关闭所有动画 | 功能组与正常动效组分开，正常动效检查不可省略 |
| 冗余清理扩大为整个 web 重写 | 只清理已被新入口替代的调用与重复动效，不顺手改算法/设计 |

## 12. 本机安全、应用与回滚

### 12.1 安全边界

- 本轮只规划；执行时也不更改照片业务后端合同、schema、识别阈值、扫描恢复、公众人物识别资料或原图。
- 验证使用独立 PHOTO_LIBRARY_DATA 和明确空闲端口，同时核对实际 web 根目录、数据目录和启动进程。换端口不等于隔离。
- 不运行日常库的测试写入，不重跑全库扫描、识别或生成推荐。
- 原有未提交工作必须保留。禁止 reset --hard、clean、任意覆盖或把用户修改混成任务成果。
- 需要隔离开发时可使用本地任务分支/worktree，但不是强制用户管理的流程；最终需明确日常版本是否已应用。
- 所有报告和测试证据只在本地交付；不向 GitHub 写入，亦不把私人照片交给外部视觉服务。

### 12.2 应用到日常使用版本

执行者先证明相关文件在隔离环境通过，再以小批文件变更应用到日常程序实际读取目录，刷新/新开页面验证。若仅静态前端改动，不为了“版本号看起来一致”擅自重启后端。

当前任务用户授权是修好本机程序，默认不需要额外上线仪式；但不能覆盖不明用户工作或中断扫描。真实阻塞写清，不将“代码改好了但没应用”混为已完成。

### 12.3 回滚单位

每阶段保存本地可恢复检查点，包括 JS、CSS、index 加载顺序和相应 smoke 调整。回滚整批兼容变更，不能只回 CSS 留 JS 类名、或只回主文件漏新模块。

本次不做数据库迁移，所以前端回滚不恢复或覆盖用户数据库。已成功的收藏、位置、命名继续保留。后端接口合同未变时不因回滚前端撤销用户操作。

## 13. 交付物和完成标准

### 13.1 控制交付数量

只需一处本地报告目录，内容为：

- `baseline.md`：版本、当前入口/补丁清单、隔离环境与基线用例。

可以在 completion 中合并清理台账，不为每个子任务生成一份新文档。不要将本任务卡本身再自动上传仓库。

### 13.2 Definition of Done

| 必要门槛 | 完成证据 |
|---|---|
| 当前画面只有一个权威源 | 可定位的控制器状态、写入点清单、state.detail 镜像说明 |
| 新照片只有一个采用入口 | commitDisplay 调用关系，正常请求/提交次数 |
| seed 与 candidate 无业务绘制资格 | VD-02/05/09 的真实入口结果 |
| 过期任务不写 DOM | VD-04/05/06/08/10/30，无 stale commit |
| 关闭时立即失效但视觉可渐隐 | 生命周期事件记录、重开与旧关闭回调测试 |
| 标签/签名/主图/收藏/地点同身份 | 帧级检查 + 代表场景截图 |
| 同图刷新不换图、不重复动画 | dirty 调度与 VD-14/26 |
| 写操作不串、数据不丢 | 隔离收藏、位置、人物操作的回执测试 |
| 动效只有一个适用 owner | ownership 表、CSS/JS 配对和正常动效录像 |
| 同容器换源不混集合上下文 | VD-28/29/30/31 |
| 导出冻结时点明确、成片稳定 | VD-35—38，源图 hash 不变 |

**性能边界：** 不以本轮重写标签算法为目标。固定同一设备、窗口、样本，记录常用 6/20 脸场景的布局次数和稳定耗时；明显重复布局/持续观察器是失败。数值波动先用重复样本核实，不因一次慢帧扩大范围。

## 14. 明确不做什么

- 不引入 React/Vue/前端构建链、Redux 类全站 store、全局事件总线、通用路由重写。
- 不把 viewer 全部拆成大量微模块，不重写 waterfall 虚拟化、分页缓存、列布局和地图聚合。
- 不新增主题、换字体、改底板、美化全站；不改变姓名展示和自动/手动布局算法。
- 不增加场景识别、语义检索、云同步、账号系统、网络服务或遥测。
- 不改变人脸识别、公众人物识别、同名合并、单张纠错、路人的业务定义。
- 不改后端照片 API、数据库 schema、EXIF、原图或现有导出资源访问白名单。
- 不为躲避错配而关闭人名、取消 seed、加固定长延迟、永久禁用正常动效。
- 不用简单截图取代原图导出，不创建双份长期存活 viewer 来掩盖生命周期问题。
- 不为了“全部统一”接管与大图无关的操作队列和业务缓存。
- 不自动打包、推送、创建 PR、上传报告或操作远程仓库。

**本轮成功不是多了多少抽象，而是以后增加一个打开入口、一个异步回执或一种换源情况时，不再需要重新猜它是否会把旧人名画出来。**

### 浏览器行为参考
