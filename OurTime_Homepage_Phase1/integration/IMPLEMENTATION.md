# Luna 本地实施说明

## 1. 先检查，随后直接在允许范围实施

先读本地 README、AGENTS、近期任务卡，以及本包全部接入说明。记录已有改动并保留。运行：

```powershell
python .\OurTime_Homepage_Phase1\tools\preflight.py --repo .
```

它只读。缺少真实项目文件时停止；不要在错误目录安装。如果当前目录存在本包三个文件的同名版本，先做 diff，不强覆盖。

新增文件可以选择以下一种方式，**不要重复应用**：

```powershell
git apply --check .\OurTime_Homepage_Phase1\01-add-files.patch
git apply .\OurTime_Homepage_Phase1\01-add-files.patch
```

或逐个复制 `files/web/` 的三个文件；后一种仅适用于确认目标不存在。补丁不修改旧文件，`git apply` 成功不代表首页已经接入。

## 2. 修改白名单

允许新增本包的三个 `web/home-query-*` 文件；允许新增一个小的 `web/home-query-init.js` 接线文件；允许对本地 `web/index.html`、`web/app.js` 做精准接线、首页标题/导航文案和控件入口调整。可新增本轮独立验收脚本/报告，不重写旧测试来“造通过”。

优先不修改 `style.css` / `appearance.css`。确需隐藏旧的首页工具容器时，用新加的、只在首页启用的 class 或原有显隐逻辑，禁止用全局选择器隐藏所有工具栏。首页标题需调整布局时也只能限定在首页。

禁止改动 Python 源文件、依赖、数据库 schema/data、扫描服务/任务、识别模型、`viewer.js`、`waterfall.js`、viewer CSS/DOM。不得全局重命名 `timeline`。不得把这次任务扩大成全站导航重构。

## 3. 加载与挂载

CSS 放在现有基础/地图/appearance 样式后，保留其他覆盖样式的加载。脚本是普通 classic script，不是 ES module，不需要 npm/build。

- `home-query-ui.js` 与 `home-query-bridge.js` 本身只导出工厂，不自动读全局 state，不自动挂载。
- 保留现有 `app.js → viewer.js → waterfall.js` 的相对顺序。
- 在现有脚本可用后，再加载/执行小的 init；也可在 app 的既有初始化末尾挂载，但不要在 `state` 尚未建立或照片加载器尚未就绪时挂载。
- 禁止把整套脚本加 `async`；禁止重复加载同一模块。使用与现有项目一致的静态资源 URL，不凭空写 `/web/...` 路由。
- 在现有首页照片网格之前、与原查询栏同一布局层级，插入一个空 host，不能放入照片网格的虚拟滚动内部。
- 完成 adapter 绑定、挂载和基本验证后，才停用首页原重复控件。挂载失败时保留旧控件，不留下空白主页。

建议 init 采用 `let homeUI = null` 后创建 bridge，然后 `homeUI = OurTimeHomeUI.mount(...)`。外部状态更新的同步钩子使用 `homeUI?.sync()`，避免初始化先后导致错误。

## 4. 原有控件如何处理

| 旧入口 | 本轮去向 |
|---|---|
| 搜索框 | 新查询栏；沿用原 q 的后端语义，不新增智能解析。停用旧首页 debounce，不能两份并存。 |
| 全部人物 | 抽屉内“人物”；选择现有 ID，不创建人物。原人物控件 ID 如仍被其他代码引用要保留/显式同步，不能直接删坏调用。 |
| 目录、只看这个目录、应用、清除 | 抽屉内文件夹路径与现有选择器。条件标签负责移除。 |
| 目录排除… | 不再出现在首页找照片栏；保留现有文件夹/已排除页中已存在的操作入口。若本地没有替代入口，先保留为该管理上下文的低频入口，不得无声丢失唯一功能。 |
| 时间倒序、时间正序 | 首页不再显示；由一个 sort 选择器承接，保留四种既有排序。不要顺手删除其他页面需要的处理函数。 |
| 按年份查看 | 确认既有 `years` 可达后移到左侧“年份”。已有入口就重命名/复用，不能再新增第二个时间线。 |
| 批量补录主入口 | “选择”。点击后才显示批量条，批量补录成为选择后的动作。 |
| 永久刷新 | 平时隐藏。复用既有扫描/图库更新状态触发条件提示，或在扫描管理上下文保留；不凭空伪造“发现 N 张”数字。 |

人物页、地点页、文件夹页、其他整理页保持原有布局与功能。本轮组件默认只在真正首页照片流 active；不要未经验证就在所有页面全局替换工具栏。

如果共享旧工具栏横跨多个照片分类，应让新旧栏的可见性由当前 view 明确决定。非首页回到原有查询栏时，必须看得见真实生效的条件，不可留下一套隐藏筛选影响结果却没有任何提示。

## 5. 标题与日期语义

首页可见主标题统一“全部照片”，保留内部 `timeline`。面包屑可为“我的照片 / 全部照片”。不再叠放“全部照片 / 按时间 / 最新的照片在前面”三层同义标题。副文字显示真实数量即可；若保留排序描述，它必须跟随最新/最早/文件名排序变化，不能永远写“最新在前”。

顶部统计仍读原数据，不硬编码截图数字。不要新增统计 API、全库扫描或新的关于页。全局添加照片入口仍连接原有流程，不改变其扫描行为。

## 6. 必须正确的交互

**唯一已应用状态**为现有 state。新组件只保存尚未应用的抽屉草稿和待提交的搜索输入，不复制一套已应用搜索系统。

应用人物 + 目录时一次性写 q/person/directory，然后仅调用一次现有“重建当前照片列表”路径。不能连续模拟旧人物 change、目录 click、搜索 input 导致多次刷新和竞争。筛选不能触发 `setView('timeline')` 导致无关清空、sort 强制变更；除非本地原调用确实需要，必须逐项证明其行为。

目录筛选与排序独立。首页通过新桥直接写 directory 后重建列表，不走旧的隐式 `name_asc` 切换；必要时仅在首页入口去掉这段联动。文件夹页自己的默认排序不在本轮变更。

选中人物后的姓名显示必须来自本地已有姓名/别名或原 label；从人物详情跳回首页也要 `sync()`。列表尚未加载或 ID 未找到时保留该 ID，不擅自清空条件。

批量选择始终使用原来的 Set、选择上限、可见屏幕定义、确认弹窗与操作函数。排除等写操作不能因为接入新按钮而跳过原确认。新按钮不调用“删除原文件”。

## 7. 验证、交付、回退

按 `ACCEPTANCE-CHECKLIST.md` 分层验证。先语法检查，再现有 `validation/smoke.py`，本轮模块测试可直接运行。不要为 UI 改动自动启动全量扫描/识别人脸/入库测试。

涉及实际页面的验证，优先使用项目既有只读检查或隔离数据；正式库不得执行补录提交、排除、恢复、合并、扫描。读取缩略图的 GET 在既有项目中可能产生缓存，不要把“无 POST”谎称为“文件系统绝对零写入”。本轮不主动清理缓存。

完成后报告：实际改动文件、每个回调接入位置、通过/失败/跳过/未验证、遗留项和回退方法。不要自动 commit 或 push，除非用户另有授权。

回退只撤销本轮接线与新增文件，恢复本轮前保存的相关片段/文件；已有用户改动保持原样。不要用 `git reset --hard` 或恢复到旧 HEAD，因为会删除本轮之前的未提交修改。
