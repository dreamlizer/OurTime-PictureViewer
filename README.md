# 拾光 · 本地照片资料库 0.3

第一版先建立照片档案：文件位置、元数据、人物、时间和地点。浏览器是操作界面，Python 后台与 SQLite 数据库在本机运行。原照片内容只读，不移动、删除或回写 EXIF。

## 打开与使用

1. 双击本目录的 **启动拾光.vbs**。它会在后台启动服务并打开默认浏览器，不常驻黑色命令窗口。
2. 页面地址是 **http://127.0.0.1:8765**。关闭浏览器不会停止后台扫描。
3. 点击“添加照片”，选择一个或多个本地照片文件夹，确认后一次开始扫描。选择文件夹只加入草稿，不会立即扫描；默认包含子目录，原照片保持原位。
4. 添加照片默认开启人脸候选生成、关闭系统目录，并使用人脸识别安全的单路处理。人脸识别优先使用本机显卡，已完成的人脸不会重算；扫描过程中可以暂停并继续。
5. 在“人物档案”核对分组、命名。误归的人脸可移出，属于同一人的分组可合并。
6. 点击照片，查看信息并补录时间、地点、备注。可用“批量补录”一次修改多张照片。留空清除人工字段后，会重新采用原始信息。
7. 在全部照片页用人物、时间、地点、文件夹组合筛选；条件同时满足才会显示。原图可在浏览器打开，也可在 Windows 文件夹中定位。
8. 不再使用时双击 **停止拾光.vbs**。它先请求暂停，再停止本项目记录的后台进程。如果正在处理的单个文件尚未结束，可稍后再试。

页面的“原始候选文件”是文件盘点总量，包含副本和素材；“累计登记”是扫描进度；“保留档案”是当前未排除且已去重的档案数量。以页面当时数字为准。

2026-09-10：正式六盘元数据已入库（D–I，不含 C；G 盘整盘排除）。人脸 GPU 补扫已结束，状态 `completed_with_errors`，已识别 `face_state=1` 不重算。新脸合并阈值为 0.50；当日已将未命名散组并入已命名人物或相互合并，1–2 张脸的未命名组改走“路人”。物体识别的工作台入口已隐藏，库内旧标签保留但不再继续扫描。库存和任务状态以页面 `/api/status` 为准，不要把验证当天的快照或文档里的瞬时数字当成现役库存。

## 添加照片、扫描、排除与粗筛

- 元数据读取使用 ExifTool 常驻进程，避免每张照片重新启动工具。含人脸识别的任务仍使用 1 路，保持候选分组顺序稳定。
- 暂停会等待已经提交的少量文件完成，再关闭读取进程；继续时先快速检查已登记文件，再处理新内容。页面显示已检查、新读取和读取问题，不把跳过旧文件的速度冒充新照片处理速度。
- “全部照片”提供人物、时间、地点、文件夹筛选，以及选择和排序；选中条件后才刷新照片，不会每输入一个字就重建列表。添加照片页只负责选择目录和启动扫描；“已排除”可查看排除档案、添加目录排除规则和恢复目录。
- 单张或批量排除按照片内容生效，所有完全相同的副本都会被排除。换一个路径重新扫描同样的内容，也不会重新加入。
- 目录排除包含子文件夹。尚未扫描的内容直接跳过；已入库内容退出保留列表。若其他未排除目录还有同内容副本，会保留该档案及共用缓存。
- 排除会删除不再使用的照片缩略图、人脸裁剪图和人脸特征记录；原照片、原始元数据、人工补录、姓名档案和排除记录保留。移除人脸后，可能需要重新确认人物归属。
- 恢复时，已入库档案可重新显示，缩略图在浏览或重扫时重建；未入库内容需要重扫，人脸需要重新识别。子目录恢复不会覆盖父目录规则，目录恢复也不会覆盖单张排除。
- 对 `._` 开头且文件头确认为 AppleDouble 的辅助文件，单独计数并跳过；此前入库的同类辅助文件标为已排除。损坏、截断等真正读取失败仍然报告，不通过放宽解码隐藏问题。
- 程序不会自行决定哪些截图或程序素材无用；这些由用户通过目录或图片选择排除。

## 连续浏览与中文地名

- 单击或双击照片打开大图。左 / 上方向键上一张，右 / 下方向键下一张；也可点击两侧按钮。Home / End 到当前范围首张 / 末张，Esc 关闭。输入框内的方向键仍用于文字输入。
- 浏览范围沿用打开时的人物、时间、地点、目录和分类筛选，固定这一次的照片顺序。扫描新增照片不会插入当前浏览序列；关闭后刷新列表即可看到新照片。从人物档案的脸部小图打开，也仅浏览该人物的照片。
- 缩略图是连续滚动的瀑布流。每次读取 24 份资料，接近底部继续加载；只创建屏幕附近的缩略图节点，离屏较远的图片移出页面，最多保留 6 批详细资料缓存。以前浏览的位置只保留轻量高度记录，向上滚动按需重新读取。图片元素另有 144 个上限，实际数量随窗口大小和图片比例变化；浏览器自身的图片缓存仍可能占用额外内存。
- 关闭大图返回打开前的滚动位置；搜索、目录、人物和排序变化会重新建立列表。“选择当前屏幕”只选择当前可见的照片，跨滚动的选择状态保留，每次最多选择 1000 张。扫描中可点击“刷新照片列表”更新当前范围，避免新照片不断插入打乱顺序。
- 支持拍摄时间正序 / 倒序、文件名自然顺序 / 倒序（例如照片 2 在照片 10 前）。选择目录后默认按文件名顺序，包含子目录；相同内容只显示一份档案，排序与名称采用范围内的副本。
- 支持适应窗口、预览原尺寸、放大缩小、拖动查看、双击缩放、全屏、3 / 5 / 10 秒自动播放。到末张自动停止，关闭查看器或切到后台标签页会停止播放。
- 看图默认接近占满窗口，详细资料收起。照片下方白边左侧显示设备、文件格式和原文件大小（KB / MB），中间显示曝光参数，右侧将时间标签、具体时间和中文地点放在一起；白边不显示分辨率。只显示真实读取的参数，缺失项不补造。点击“详细资料”打开右侧浮层，不挤小照片；人工补录放在其中的折叠区。横图与竖图保持原比例完整显示，较小预览可适度放大。
- 点击照片外的空白、底部白边或外侧遮罩可关闭大图。照片本身、功能按钮、链接与详细资料区继续响应各自操作；从照片开始拖动到外部不会触发关闭。
- 大图按需读取，最长边 2560 像素，方向按原始拍摄信息校正。只使用浏览器缓存，不新增大图磁盘缓存；“预览原尺寸”指这份预览的尺寸，查看原始像素使用“打开原图”。不能解码时明确提示，可继续翻图。
- 原有资料补录保留，未保存的输入在翻图时暂存在当前页面，刷新页面会丢失。没有增加裁剪、调色或修改原照片的图像编辑功能。
- 国内自动地名使用离线数据的中文别名，并优先与本机行政区划名称表核对，避免优先使用过时别名；国外使用拉丁字母地名及英文国家名。无法找到中文别名时显示“地名待确认”，不自动造译名。来源仍是最近聚居地参考，不能当作精确行政区或地址。
- 已登记的旧自动地名通过 `tools/localize_places.py --data <资料库目录>` 更新，原始元数据、坐标和人工补录不改写。升级前应先备份数据库。
- 离线地点按空间网格检索，并缓存重复坐标；列表排序仅处理轻量字段后再读取本页信息。扫描并发上限 4 路，完成时间按真实目录实测。

## 当前已实现

- 浏览和选择本机目录；一次可提交多个目录；递归扫描常见图片与常见相机 RAW 扩展名。
- 默认排除 Windows、Program Files、ProgramData、AppData、回收站、虚拟环境、依赖缓存等目录；页面可选择包含这些目录。不跟随目录链接，不主动下载云端占位文件。
- 文件 SHA256、大小、修改时间、完整路径入库。完全相同的内容关联到同一档案，保留多个文件位置，不自动删除重复文件。
- ExifTool 13.59 读取 EXIF、GPS、XMP、IPTC 及其支持的相机标签，保存带分组的原始字段；Pillow / pillow-heif 负责常见图片与 HEIC 预览。无法解码的格式也尽可能保留元数据，并明确列出预览读取问题。
- 优先采用原始拍摄时间，其次元数据数字化时间，再使用可识别的文件名日期，最后记录文件修改时间参考。时间来源明确显示，原始时区字段保存在元数据中；第一版没有跨时区时间线换算。
- 保存 GPS 坐标；使用现有 GeoNames cities500 离线数据提供 80 km 内最近聚居地参考及距离。国内用中文，国外用拉丁字母地名及英文国家名。它不是省市区边界判定，也不是精确拍摄地址。
- 人工时间可精确到年、月、日，或保存“2012 年夏季”等大致描述；独立保存，不伪造精确时间。保留人工修改记录。
- InsightFace buffalo_l 本地人脸检测和特征比对，生成待核对分组；已命名人物的新相似人脸作为候选提示，需人工合并确认。可命名、合并、单张人脸拆分。
- 扫描暂停、增量重扫、断电或进程中断后的恢复入口。继续扫描会重新遍历目录并跳过已完成文件；损坏文件会重试。
- 同内容文件改名或搬家后重扫，关联原档案与标注；确认不存在的旧路径标记缺失。无法读取的目录或文件会记录错误。
- 照片列表、人物页、缺失时间 / 地点、重复副本、读取问题、原文件缺失等筛选。
- 在线 SQLite 一致性备份、JSON 清单导出。API 只监听 127.0.0.1，拒绝跨站写入；没有上传照片的功能。

## 界面样式维护

页面使用统一的导航、控件与弹窗样式；照片流、人物、年份、地点和大图按内容采用不同布局。新增的 `web/appearance.css` 在基础样式和地图样式之后加载，集中维护配色、字号、控件状态与响应式调整，不依赖外部字体资源或新的前端框架。

- 侧栏使用内嵌 SVG 图标，窄窗口保留图标及可访问名称；统计区在手机宽度下排成两列。
- 人物卡片的命名入口位于头像与姓名下方；大图工具按缩放、查看、人物标签、资料与播放分组。
- 全部照片、文件夹、地点、合影和人物档案的顶栏、标题与工具区在滚动时保持可见；窄屏仍需避免横向溢出。大图“素笺”主题使用 `web/vendor/fonts/` 内置的屏幕阅读版文楷；“茶棕”主题内置 Ma Shan Zheng、Long Cang、Liu Jian Mao Cao 三款毛笔字体并默认使用 Ma Shan Zheng。图片标签可调字号和底牌透明度，其余固定项留在同一菜单内置灰。
- 修改照片说明样式时保留瀑布流的 42 px 说明高度；大图照片元数据题注栏按照片显示宽度自适应为 68 / 86 / 96 px，并与缩放逻辑联动。
- 地图定位图标在 `web/vendor/images/`，与本地 Leaflet 1.9.4 配套；地图底图仍需要联网。

本轮界面调整的原版本、前后截图与检查记录位于 `validation/reports/appearance-20260909/`。刷新页面即可加载样式，无需重启扫描服务。

## 数据保存在哪里

| 内容 | 位置 |
| --- | --- |
| 正式数据库（含人物特征、姓名、标注和修改记录） | `data/library.sqlite3` |
| 照片缩略图、人脸裁剪图 | `data/thumbs/`、`data/faces/` |
| 页面“备份资料库”生成的一致性备份 | `data/backups/` |
| 后台日志 | `data/server.log`、`data/server-error.log` |

**备份数据库不等于备份原照片。** 原照片仍在原来的磁盘和目录中。移动到其他电脑时，除了原照片，还需保留完整 `data` 目录和必要运行环境。JSON 导出方便检查与迁移，但不包含人脸特征向量；完整恢复以数据库备份为准。第一版没有页面内一键恢复功能，恢复时应先停止后台。

## 第一版的边界

- 正式库已完成 D–I 元数据入库和人脸 GPU 补扫（不含 C；G 盘整盘排除），人物准确率仍未做家庭照片验收。模型验证用的是 InsightFace 自带测试合照，不能据此推断识别准确率。容量与速度以页面 /api/status 和当日任务记录为准。
- 只自动归集完全重复的内容。压缩、裁剪、编辑版本仍是不同档案，尚未做视觉相似照片管理。
- 人脸相似度阈值是初始规则，不是经个人照片校准的准确率。小脸、模糊、侧脸、儿童成长与相似亲属可能漏分或误分，必须允许人工核对。
- 只把明确命名视为人物确认，尚未做“排除此人”的长期负样本学习。单张移出或人工合并均记录历史，未来重扫不会重算已完成的人脸。
- 模糊时间按文本保存，尚未把自然语言日期转换为可计算的起止区间。页面支持人物、时间、地点、文件夹组合筛选及排序；后端仍保留关键词 q，供高级搜索使用。
- 相机 RAW 的元数据支持范围取决于 ExifTool；RAW 预览、人脸检测没有保证全部支持。相机私有标签和二进制块也不能保证全部被解析；原文件始终保留。
- 地点页已有本机 Leaflet 地图和人工改名；公开离线库没有小区/景区细名时，只能手填覆盖，不能当成精确门牌。仍不包含自动事件分组、OCR、场景语义搜索、文件搬迁、自动删除、视频和 Live Photo 配对。
- 当前人物匹配适合先验证小中规模照片库；超大规模人脸向量索引仍需实库测量后优化。元数据常驻处理和并发已实现，但整体完成时间应按实际新增照片速度持续估算。
- 目前仍是一边遍历目录、一边采集元数据和缩略图；另有全盘轻量计数结果。尚未实现把所有未处理文件都写入待筛清单的独立第一阶段，也没有自动判断截图是否有用。

## 验证

日常页面改动先跑 `python validation/smoke.py`：静态防呆，现役 8765 空闲时再冒烟接口，目标几秒结束，不启新服务、不停正式扫描。添加照片与首页只读入口检查用 `python validation/validate_add_photos_flow.py`；入库 / 人物 / 扫描合同仍用隔离核心路径：`python validation/validate.py`，临时后台默认 8766。依赖 Playwright；会复用 InsightFace 自带 `t1.jpg`。证据：`validation/reports/smoke.json`、`validation/reports/validation.json`。

专项脚本：

- `validation/validate_upgrade.py`：并发、排除恢复、辅助文件；`upgrade-validation.json`
- `validation/validate_browse.py`：浏览范围、排序、方向键、中文地名；`browse-validation.json`
- `validation/validate_photo_frame.py`、`validation/verify_caption.py`、`validation/validate_waterfall.py`、`validation/verify_motion.py`：大图白边、瀑布流与动效
- 正式页面只读检查：`validation/verify_live_browse.py` 等 `*-live*.json`

2026-09-07 已通过隔离核心 / 排除 / 浏览检查，以及正式页面只读浏览、白边、瀑布流和动效检查。当时正式库约四万份档案，旧自动地名更新 7,324 条，签名不变。这些是当日证据，不是当前库存快照。
